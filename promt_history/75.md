

# P75 — Stability Layer (Confidence + Minimum Sample)

We now have a working epsilon-greedy bandit system.

However, it reacts to small statistical noise.

We want to add a **stability layer** so that:

- small differences DO NOT trigger rebalance
- only statistically meaningful differences trigger allocation shifts

---

# 🎯 GOAL

Prevent overreaction to noise while preserving fast reaction to real winner shifts.

---

# 🔧 TASK

## 1. Minimum Sample Gate

Rebalance should NOT happen unless BOTH variants have enough data.

Define:

- minimum exposures per variant
- minimum conversions per variant (optional)

Example:

- exposures >= 100
- conversions >= 5

If not met:

→ NO rebalance

---

## 2. Confidence Threshold (Practical)

We do NOT need full statistical testing (no heavy math libraries).

Instead, define a simple rule:

```
delta = |CR_A - CR_B|
```

Only rebalance IF:

- delta is above a threshold (e.g. 20–30% relative difference)
- OR absolute difference exceeds a small floor

Example:

- A = 2.0%
- B = 2.2% → ignore

- A = 2.0%
- B = 4.0% → accept

Rebalance ONLY IF:

- minimum sample satisfied
- AND confidence threshold satisfied

→ keep current weights

# ✅ Design Response — P75

## Where the stability layer lives

All changes belong exclusively in `detectLeadingVariant`. This function already acts as the single gate between "we have data" and "we have a decision." If it returns `null`, `maybeRebalance` exits silently at line 200 — no rebalance, no KV write, no cooldown consumed. The rest of the pipeline (cooldown logic, weight computation, KV write) stays untouched.

---

## 1. Minimum Sample Gate

**Current state:** `eligible = performance.filter(v => v.exposures >= 100)` — exposures only.

**Problem:** 1 conversion out of 100 exposures (1.0% CVR) is a real but extremely noisy signal. A second variant with 0/100 (0.0% CVR) passes the exposure gate, and the 1.0% leader wins immediately even though this is likely noise.

**Addition — minimum conversions per variant:**

```
eligible = variants where:
  - exposures  >= MIN_VARIANT_EXPOSURES   (100, unchanged)
  - conversions >= MIN_VARIANT_CONVERSIONS (3, new)
```

**Why 3, not 5:** Minimum conversions should be the lowest number that rules out pure luck, without demanding so much data that low-traffic experiments never rebalance. At 3 conversions:
- 3/100 = 3.0% — meaningful enough to compare
- 0/100 = fails gate → no winner declared until both sides have signal

**Effect on the "proove" dataset:**
- A: 732 exp, 15 conv → ✓ (15 ≥ 3)
- B: 788 exp,  9 conv → ✓ (9 ≥ 3)
- Gate passes → proceeds to delta check.

---

## 2. Confidence Threshold (delta)

**Current state:** `detectLeadingVariant` picks the highest CVR unconditionally. A difference of 2.0% vs 2.1% triggers a rebalance.

**Rule:**
```
delta_abs = leader.conversion_rate - runner.conversion_rate
delta_rel = delta_abs / max(runner.conversion_rate, 0.001)   ← avoid div-by-zero

rebalance only if:
  delta_abs >= DELTA_ABS_FLOOR (0.005 = 0.5pp)
  OR
  delta_rel >= DELTA_REL_THRESHOLD (0.20 = 20% relative)
```

**Rationale for OR (not AND):** The two conditions cover complementary regimes:
- Low-CVR experiments (both variants near 1%): relative difference is large even on small absolute gaps → absolute floor prevents thrashing.
- High-CVR experiments (both variants near 15%): a 3pp gap is a large absolute difference but only 20% relative → relative threshold catches this correctly.

**Recommended defaults:**
| Constant | Value | Meaning |
|---|---|---|
| `DELTA_ABS_FLOOR` | `0.005` | Minimum 0.5pp absolute CVR gap |
| `DELTA_REL_THRESHOLD` | `0.20` | OR minimum 20% relative CVR gap |

**Worked examples:**

| A CVR | B CVR | delta_abs | delta_rel | Decision |
|---|---|---|---|---|
| 2.0% | 2.2% | 0.2pp | 10% | ❌ ignore — small noise |
| 2.0% | 2.5% | 0.5pp | 25% | ✅ accept — 20% relative threshold met |
| 2.0% | 4.0% | 2.0pp | 100% | ✅ accept — both thresholds met |
| 1.0% | 1.4% | 0.4pp | 40% | ✅ accept — relative threshold met despite small absolute |
| 0.5% | 0.6% | 0.1pp | 20% | ✅ borderline — exactly at relative threshold |
| 0.0% | 2.0% | 2.0pp | — | ✅ accept — but B fails conversion gate (0 conv) → null anyway |

---

## 3. Combined Rule (full decision flow)

```
detectLeadingVariant(performance):

  Step 1 — Eligibility gate:
    eligible = variants where
      exposures  >= 100  AND
      conversions >= 3
    if eligible.length < 2 → return null

  Step 2 — Sort by CVR descending:
    leader = eligible[0]   (highest CVR)
    runner = eligible[1]   (second highest)

  Step 3 — Delta check:
    delta_abs = leader.conversion_rate - runner.conversion_rate
    delta_rel = delta_abs / max(runner.conversion_rate, 0.001)
    if delta_abs < 0.005 AND delta_rel < 0.20 → return null

  Step 4 — Return winner:
    return { winner: leader.slug, confidence: true }
```

`maybeRebalance` is unchanged. All stability logic is contained in step 1–3 above.

---

## 4. Cooldown Interaction

The stability layer integrates cleanly with the P77 winner-shift override:

| Scenario | detectLeadingVariant | maybeRebalance outcome |
|---|---|---|
| Delta too small | → `null` | Exits at line 200. No rebalance. Persisted cooldown untouched. |
| Delta OK, same winner, cooldown active | → `{ winner }` | Respects persisted cooldown → no rebalance |
| Delta OK, same winner, cooldown expired | → `{ winner }` | Normal rebalance |
| Delta OK, winner changed | → `{ winner }` | Bypasses persisted cooldown (P77 T1) → immediate rebalance |

**Key property:** A winner change only bypasses the persisted cooldown if the delta is above threshold. A weak winner flip (2.0% → 2.1%) returns `null` from step 3 and never reaches the cooldown override logic. The bypass is earned, not automatic.

---

## 5. Edge Cases

**One variant has 0 conversions:**
- The 0-conversion variant fails `MIN_VARIANT_CONVERSIONS = 3` → `eligible.length < 2` → null.
- No rebalance. System waits until the trailing variant accumulates at least 3 conversions.
- This prevents immediate 90/10 allocation based on the first lucky conversion on one side.

**Very low exposure (< 100 on either side):**
- Caught by the existing exposure gate (unchanged at 100).
- System stays at initial weights until both variants have meaningful traffic.

**Sudden spike:**
- A sudden conversion burst (e.g., promotional traffic) produces a large delta_abs and delta_rel simultaneously → both thresholds pass → system correctly reacts.
- If the spike is so recent that conversion count is still < 3, the gate prevents premature action.
- Once the spike persists through a rebalance window (5 min), it becomes the new baseline.

**Both variants have identical CVR (including 0/0):**
- delta_abs = 0, delta_rel = 0 → both below thresholds → null → no rebalance.
- Correct: tie means no basis for a decision; current weights preserved.

---

## 6. Trade-offs (sensitivity vs stability)

| Parameter | If too high | If too low |
|---|---|---|
| `MIN_VARIANT_EXPOSURES` | Low-traffic experiments never rebalance | Rebalance on statistically meaningless samples |
| `MIN_VARIANT_CONVERSIONS` | Experiments with low CVR never rebalance | Single lucky conversion triggers shift |
| `DELTA_ABS_FLOOR` | Misses real gains in low-CVR products | Rebalances on every minor fluctuation |
| `DELTA_REL_THRESHOLD` | Slow to react to meaningful improvements | Over-sensitive in high-CVR experiments |

**Recommended starting point for this system** (validated against real data):
```js
const MIN_VARIANT_EXPOSURES   = 100;    // unchanged
const MIN_VARIANT_CONVERSIONS = 3;      // new
const DELTA_ABS_FLOOR         = 0.005;  // 0.5pp
const DELTA_REL_THRESHOLD     = 0.20;   // 20% relative
```

These values make the "proove" dataset (732 exp / 15 conv vs 788 / 9 conv, delta = 0.91pp / 80% relative) trigger a rebalance comfortably. They would NOT trigger on a 2.0% vs 2.2% scenario (10% relative, 0.2pp absolute — below both floors).
