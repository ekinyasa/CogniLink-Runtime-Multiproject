

PROMPT 71 — Automatic Traffic Rebalancing (Bandit Layer)

Goal

The experimentation engine is now complete for:

• deterministic routing
• exposure tracking
• click telemetry
• conversion telemetry
• cookie attribution
• analytics calculations

The next step is to allow the system to **adapt traffic automatically** based on observed performance.

This introduces a lightweight **multi‑armed bandit layer** on top of the existing A/B router.

Important constraint:
The deterministic router must remain intact.  
Bandit logic only adjusts **variant weights**, not routing logic.

---

Task 1 — Strategy field

Experiments gain an optional field:

strategy

Possible values:

"fixed"      → current behavior (default)
"epsilon"    → epsilon‑greedy bandit

Example experiment record:

{
  alias: "prf",
  state: "RUNNING",
  strategy: "epsilon"
}

If strategy is missing → treat as `"fixed"`.

---

Task 2 — Performance snapshot helper

Create helper:

getExperimentPerformance(alias)

Return for each variant:

• exposures
• clicks
• conversions
• conversion_rate

Example:

[
 { slug:"A", conversion_rate:0.021 },
 { slug:"B", conversion_rate:0.013 }
]

Use existing analytics tables; do not recompute historical metrics.

---

Task 3 — Winner detection

Add helper:

detectLeadingVariant(performance)

Rules:

• minimum exposures per variant: 100
• winner = highest conversion_rate
• ignore variants below threshold

Return:

{ winner:"slug", confidence:true }

or

null

---

Task 4 — Epsilon‑greedy rebalance

If experiment.strategy == "epsilon":

Compute weights as:

90% → leading variant  
10% → evenly split across remaining variants

Example:

variants: A B C  
winner: B

weights:

B → 90  
A → 5  
C → 5

Important:

• do NOT modify router algorithm
• only update stored experiment weights

---

Task 5 — Rebalance trigger

Run rebalance when:

• new conversion recorded
OR
• exposure count crosses 500 boundary

Guard:

rebalance at most once every 5 minutes.

Store timestamp:

experiment.last_rebalance

---

Task 6 — Safe weight update

Weight update must:

1. preserve total weight = 100
2. write update atomically
3. log change

Example log:

[BANDIT]
alias: prf
winner: proove-ttbio
old_weights: [50,50]
new_weights: [90,10]

---

Task 7 — Debug visibility

Extend existing endpoint:

/api/experiment/debug/:alias

Add:

• strategy
• current weights
• last_rebalance
• detected_winner

Example response:

{
 alias: "prf",
 strategy: "epsilon",
 detected_winner: "proove-ttbio",
 weights: [
  {slug:"proove-ttbio", weight:90},
  {slug:"proove-igbio", weight:10}
 ],
 variants:[ ...metrics... ]
}

---

Expected Behavior

Before learning:

traffic
50 / 50

After sufficient data:

system detects higher conversion rate

traffic shifts automatically:

90 / 10

Router behavior remains deterministic; only weights change.

This converts the experimentation system from **static A/B testing** into a **self‑optimizing experimentation engine**.

## Implementation Summary

### Files created

**`functions/_shared/bandit-rebalance.js`** (NEW)

Single-owner module for all epsilon-greedy rebalancing logic. Exports:

| Export | Task | Description |
|---|---|---|
| `getExperimentPerformance(env, alias, config)` | T2 | Reads `getExpCounters()` — same source as analytics panel |
| `detectLeadingVariant(performance)` | T3 | Min 100 exposures per variant; returns `{ winner, confidence: true }` or `null` |
| `computeEpsilonWeights(variants, winnerSlug)` | T4 | 90% winner / 10% split among rest; largest-remainder integer math |
| `maybeRebalance(env, alias, trigger)` | T5+T6 | Guarded fire-and-forget rebalance; 5-min cooldown; atomic KV write + cache invalidation |

Key design decisions:
- **Dual cooldown**: in-memory check (`cacheGet`) for fast path within the same isolate; `config.last_rebalance` for persistence across restarts
- **Atomic write**: single `CAMPAIGN_REGISTRY.put()` spreading all existing config fields, changing only `variants[].weight` and `last_rebalance`
- **Cache invalidation**: calls `cacheDelete(AB_CACHE_PREFIX + alias)` so the router picks up new weights within ≤ 60 s
- **Log format**: `[BANDIT] { alias, winner, trigger, old_weights, new_weights }`

- Added `import { maybeRebalance } from "./_shared/bandit-rebalance.js"`

  ```js
  if (expResult.counterPromise && abConfig.strategy === "epsilon" && Math.random() < 0.002) {

  ```
- `0.002` ≈ 1/500 — approximates "crosses 500 boundary" without reading all shards at request time; the 5-min cooldown inside `maybeRebalance` prevents over-firing

### Architecture notes

- **Router unchanged**: `ab-router.js → selectABVariant()` is never touched; only stored weights in KV change
- **strategy field**: experiments without `strategy` field default to `"fixed"` (no automatic rebalancing)
- **Separation of concerns**: this epsilon-greedy module is independent from the Thompson sampling module (`bandit.js` / `cron/bandit-update.js`); both can coexist
- **Minimum data gate**: 100 exposures per variant AND at least 2 eligible variants before any rebalance fires; prevents premature exploitation on new experiments
