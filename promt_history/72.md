## Implementation Summary

### Phase 1 — Root Cause Findings

**Root Cause 1 (primary — caused ALL symptoms):**

Strategy field polarity was wrong. The guard `(config.strategy ?? "fixed") !== "epsilon"` defaults to `"fixed"` (no-op) for experiments without the strategy field. Since all experiments created before P71 have no strategy field, `maybeRebalance` exited at Guard 3 on every call without ever rebalancing. The debug endpoint had the same gate: `detected_winner` was only computed when `config.strategy === "epsilon"`, returning `null` for all legacy experiments.

**Root Cause 2 (secondary — wasted 5-minute cooldown windows):**

The cooldown claim (`cacheSet(coolKey, ...)`) ran *before* the strategy check. Each conversion on a non-epsilon experiment would:
1. Clear the in-memory cooldown gate
2. Claim the slot for 5 minutes
3. Exit at the strategy check (no-op)

This burned the cooldown window, meaning even after fixing the strategy field the first rebalance would be delayed up to 5 minutes.

**Data integrity:** Clean. All counter keys consistent across `incrementExpCounter`, `getExpCounters`, and the bandit reader.

---

### Phase 2 — Minimal Fixes

**`functions/_shared/bandit-rebalance.js`**

Two changes:

1. **Strategy polarity flip**: `strategy: "fixed"` is now an explicit opt-out; absent / "epsilon" opts in.
   ```js
   // Before (P71 — broken default)
   if ((config.strategy ?? "fixed") !== "epsilon") return;

   // After (P72 — correct default)
   if (config.strategy === "fixed") return;
   ```

2. **Cooldown claim moved after strategy+state check**: No more burning the 5-minute window on no-op exits.
   ```
   Old order: cooldown check → claim cooldown → KV read → strategy check → ...
   New order: cooldown check → KV read → strategy check → state check → claim cooldown → persisted cooldown check → ...
   ```

**`functions/api/experiment/debug/[alias].js`**

Removed `strategy === "epsilon"` gate from `detectLeadingVariant` call. `detected_winner` is now always computed from the current counter snapshot — it describes data, not policy. Useful for all experiments regardless of strategy setting.

**`functions/[[path]].js`**

Exposure trigger gate changed from `abConfig.strategy === "epsilon"` to `abConfig.strategy !== "fixed"` — consistent with the new opt-out semantics.

### Phase 3 — Validation Plan

**Step 1: Verify detected_winner is populated**

Call `GET /api/experiment/debug/<alias>` with sufficient data (≥100 exposures per variant). With 2178/2334 exposures and 32/58 conversions:
```json
{
  "detected_winner": "<variant-B-slug>",
  "weights": [{"slug":"<A>","weight":50}, {"slug":"<B>","weight":50}]

```

**Step 2: Force a rebalance immediately**

Send a conversion ping:
```bash
curl -X POST /api/experiment/conversion \
  -H "Content-Type: application/json" \
  -d '{"alias":"<alias>","variant":"<variant-B-slug>"}'
```

Then wait ≤60 s for the KV cache to expire and re-call the debug endpoint.

**Expected Worker log (CF Tail / Wrangler dev):**
```
[BANDIT] {"alias":"<alias>","winner":"<B>","trigger":"conversion","old_weights":[50,50],"new_weights":[10,90]}
```

**Step 3: Verify weights shifted**

`GET /api/experiment/debug/<alias>` should now return:
```json
{
  "detected_winner": "<variant-B-slug>",
  "last_rebalance": 1710681234567,
  "weights": [{"slug":"<A>","weight":10}, {"slug":"<B>","weight":90}]
}
```

**Step 4: Verify routing changed**

After the 60 s cache TTL, run 100 test requests. Approximately 90% should resolve to variant B. Use curl with unique CF-Ray headers:
```bash
for i in $(seq 1 100); do
  curl -s -H "cf-ray: $(openssl rand -hex 8)-TST" /api/experiment/debug/<alias>
done
```
Count variant distribution in logs.

**Step 5: 5-minute cooldown holds**

Send another conversion immediately after Step 2. Check Worker logs — no second `[BANDIT]` line should appear within 5 minutes. `last_rebalance` should be unchanged on the next debug call.
