# ✅ Implementation — P77

## Files changed

### 1. `functions/_shared/bandit-rebalance.js` — Task 1

Restructured `maybeRebalance` to support winner-shift cooldown override.

**Key changes:**
- Performance snapshot (`getExperimentPerformance`) moved **before** the persisted cooldown check — so we can compare the new winner against the stored one before deciding whether to respect the cooldown
- Added `winner_at_last_rebalance` comparison:
  - Same winner → respect `config.last_rebalance` cooldown (prevents thrashing)
  - Different winner → bypass persisted cooldown, reallocate immediately
- `winner_at_last_rebalance` now stored in the KV write alongside `last_rebalance`
- `winner_changed` boolean added to `[BANDIT]` observability log

**Guard order (final):**
1. In-memory cooldown (fast path, per-isolate)
2. KV read + strategy/state check
3. Claim in-memory cooldown slot (only after opt-in confirmed)
4. Performance snapshot
5. Winner detection
6. Persisted cooldown with winner-shift override
7. Compute weights → no-op check → KV write

---

### 2. `functions/api/experiment/debug/[alias].js` — Task 2 (Option B)

Replaced single `detected_winner` field with dual-field model:

```json
"current_leader":      "slug"   // computed from LIVE telemetry at query time
"last_applied_winner": "slug"   // stored in config.winner_at_last_rebalance
```

- `current_leader` answers: "who is winning RIGHT NOW?"
- `last_applied_winner` answers: "who was winning WHEN WEIGHTS WERE SET?"
- When equal → system is consistent
- When different → a leadership shift occurred; rebalance is pending or within cooldown

---

### 3. `functions/_shared/admin-renderer.js` — Task 3

**HTML additions:**
- `<p id="exp-alias-info">` — alias info line shown after experiment loads (clickable link to `/alias`)
- Table header: "Traffic" → "Exposures"; added "Target Wt%" column (now 8 columns total)
- `<p id="exp-weight-note">` — mismatch warning shown when actual share deviates from target by >12pp

**JS DOM refs added:**
- `elExpAliasInfo` — alias info paragraph
- `elExpWeightNote` — weight mismatch note paragraph

**`loadExpResults` logic:**
- Alias info line: shows `[/alias →]` as clickable link after data loads; resets on each new load
- Variant slugs: wrapped in `<a href="/<slug>" target="_blank">` — clicking opens the canonical URL
- Weight column: renders `v.weight + "%"` from the `/api/experiments` response; shows `—` when null
- Mismatch note: computed from `totalExp`; displayed when `|actualShare - targetShare| > 0.12` for any variant with known weight
  - Text: "Distribution reflects live routing, not target weights — actual share may lag after a rebalance."
