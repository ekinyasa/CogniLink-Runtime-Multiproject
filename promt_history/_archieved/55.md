## 1 — How is the user fingerprint computed?

The "fingerprint" is the **Cloudflare Ray ID** (`cf-ray` header), read verbatim in `[[path]].js` line 207:

```js
// [[path]].js:207
const requestId = request.headers.get("cf-ray") || crypto.randomUUID?.() || "";
```

`requestId` is passed through `resolveExperimentVariant(request, abConfig, env, { alias, canonicalSlug, requestId, modifier })` and lands in `selectABVariant(config, requestId)` in `ab-router.js`:

```js
// ab-router.js:212–213
const hex    = String(requestId || "").replace(/[^0-9a-f]/gi, "").slice(-8) || "0";
const bucket = parseInt(hex, 16) % 100;
```

The bucket input is: **last 8 hex characters of the cf-ray ID, parsed as a hexadecimal integer, modulo 100**.

## 3 — How is the variant bucket computed?

```js
// ab-router.js:211–222  (selectABVariant)
export function selectABVariant(config, requestId) {
  const hex    = String(requestId || "").replace(/[^0-9a-f]/gi, "").slice(-8) || "0";
  const bucket = parseInt(hex, 16) % 100;   // 0–99

  let cumulative = 0;
  for (const variant of config.variants) {
    cumulative += variant.weight;
    if (bucket < cumulative) return variant.slug;
  }

  // Defensive fallback — unreachable when weights sum to 100
  return config.variants[config.variants.length - 1].slug;
}
```

Pattern: `parseInt(last8hex(cf-ray), 16) % 100` → linear cumulative-weight walk → first variant whose cumulative weight exceeds the bucket is selected. No hash mixing, no HMAC — purely the tail of the cf-ray ID.

## 4 — Is assignment deterministic and sticky for the same user?

**Two separate mechanisms must be distinguished:**

### First-visit assignment — NOT user-deterministic
`cf-ray` is unique per HTTP request, not per user. A returning visitor generates a new cf-ray on every request. If there were no cookie, the same user would land in a different bucket on every page load. **The cf-ray alone provides no cross-request determinism.**

### Return-visit stickiness — cookie-deterministic
The code in `experiment-router.js` lines 118–130 handles this:

```js
// experiment-router.js:118–130
const cookieName    = "exp_" + alias;
const cookieVariant = readCookie(request, cookieName);
const validSlugs    = experimentConfig.variants.map((v) => v.slug);

if (cookieVariant && validSlugs.includes(cookieVariant)) {
  // Returning visitor — honour stored assignment (no new cookie needed)
  finalSlug       = cookieVariant;
  isNewAssignment = false;
} else {
  // New visitor (or stale/invalid cookie) — pick variant by weight distribution
  finalSlug       = selectABVariant(experimentConfig, requestId);
  isNewAssignment = true;
}
```

Cookie written on first visit:
```js
// cookie-utils.js:buildSetCookie
`exp_${alias}=${variantSlug}; Path=/; Max-Age=2592000; SameSite=Lax; Secure`
```
Max-Age = 2 592 000 s = **30 days**.

**Summary:**
| Scenario | Deterministic? |
|---|---|
| Same browser, cookie present, valid slug | ✅ Always same variant |
| Same browser, cookie cleared / expired | ❌ New random assignment via cf-ray |
| Incognito / new device | ❌ New random assignment via cf-ray |
| `validSlugs.includes(cookieVariant)` fails (old config) | ❌ Re-assigned via cf-ray |

Stickiness is **browser-cookie-scoped**, not user-identity-scoped.

## 5 — Does the router ever perform learning or weight updates?

**Confirmed: no.** The entire routing path is read-only with respect to `ab_config:*` KV keys.

| Operation | Reads? | Writes? | What key? |
|---|---|---|---|
| `loadABConfig(alias, env)` | ✅ | ❌ | `ab_config:<alias>` (read only) |
| `selectABVariant(config, requestId)` | ✅ | ❌ | pure function, no KV |
| `readCookie(request, name)` | ✅ | ❌ | request header only |
| `buildSetCookie(name, value)` | — | — | pure string, no KV |
| `incrementExpCounter(env, alias, slug, "exposure")` | ✅ | ✅ | `exp:<alias>:<slug>:exposure:<shard>` — counter keys only, **never** `ab_config:*` |
| `generateExposureToken(alias, finalSlug, env)` | — | — | no KV reads or writes |

The only writer of `ab_config:*` keys is `rebalanceExperiment()` in `functions/cron/bandit-update.js`, which runs exclusively outside the request path (cron or admin trigger).
