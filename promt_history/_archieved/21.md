Example:

```

```

should redirect to a campaign's **default slug**.

Example:


2. The default slug must be chosen from the campaign's existing slugs.

Example scenario:

Early campaign → IG is main source


Later campaign → YouTube drives traffic


Alias `/launch` must follow the currently selected default slug.

# Response — Prompt 21 Implementation

All 7 tasks addressed.

## PART 1 — Alias routing auto-activate (VERIFIED + CLEANUP)

Auto-compile was already implemented in 20.md via `context.waitUntil(compileRoutes(...))` in all 4 alias-write API handlers. Implementation is deterministic: KV write completes before `waitUntil` fires; Workers Cache is invalidated by `invalidateRoutes()` inside `compileRoutes()`.

Cleanup: Removed stale "Run POST /api/admin/compile-routes to activate routing." notes from `[name].js` inline strings.

## PART 2 — Campaign alias → selectable default slug (DONE)

**`functions/_shared/route-compiler.js`** — Phase A now honors `campaign.defaultSlug`:
- After reading the campaign record from LINKHUB_CAMPAIGNS, checks for `defaultSlug` field.
- Validates: slug exists in LINKHUB_SLUGS, is active (`isActive !== false`), belongs to this campaign.
- If valid → uses `defaultSlug` as `canonicalSlug`; otherwise falls back to first active slug with a `skipped` log entry.

**`functions/api/campaign/[name].js`** — PATCH accepts `defaultSlug: string | null`:
- `null` = clear; `string` = set; omitted = no change.
- Validates slug exists in LINKHUB_SLUGS and belongs to this campaign before saving.

**`functions/_shared/admin-renderer.js`** — Campaigns tab:
- Each campaign row now shows a "Default slug:" dropdown listing all active slugs for that campaign.
- Selecting a new value fires `PATCH /api/campaign/:name` with `{ defaultSlug }` immediately.
- Dropdown hidden when campaign has no slugs yet.

## PART 3 — Background self-test structured diagnostics (DONE)

`functions/_shared/admin-renderer.js` `runBgTest()`:
- On failure, UI now appends ` · stage: <stage> (<reason>)` to the status line.
- Example: `✖ Background test failed · 4231ms · stage: analytics (AE timeout) · Mon, 09 Mar 2026 07:00:00 UTC`

Backend already returned `{stage, reason}` from 20.md PART 5.

## PART 4 — Slug test filter lifecycle (DIAGNOSIS — NO CODE CHANGE)

**Test fixture lifecycle:**
1. `createFixture(env)` writes: `ROUTE_TABLE[route:{alias}]`, `ROUTE_TABLE[route:{alias}@offer]`, `ROUTE_TABLE[route:{alias}@vsl]`, `LINKHUB_SLUGS[slug]`, `LINKHUB_CAMPAIGNS[campaign]`
2. Fixtures ARE visible in admin UI during the test run (< ~2 min).
3. `archiveFixture(env, fixture)` deletes all 3 ROUTE_TABLE keys, deletes `LINKHUB_SLUGS[slug]`, updates `LINKHUB_CAMPAIGNS[campaign]` to `isActive: false` (NOT deleted — stays for analytics).
4. After archival: slug not visible (record deleted); campaign hidden by default (isActive=false, filtered out unless "Show archived" is on).

**Conclusion:** No bug found. The 20.md PART 6 fix (`slug.startsWith("test-")`) already ensures test slugs are correctly filtered in the Campaign Links table.

## PART 5 — Admin verify endpoint returns JSON (DONE)

`functions/api/admin/verify.js` completely rewritten:
- Always returns JSON (was HTML).
- Live alias: `{ ok: true, alias, campaign, slug, defaultUtms, links: [{ label, url }] }`
- Missing alias: `{ ok: false, alias, reason: "not_in_route_table" }`
- Never throws parse errors — all paths return valid JSON.
- HTML preview removed (was causing parse errors; JSON more useful for diagnostics).

## PART 6 — Admin panel version (DONE)

`functions/_shared/admin-renderer.js`:
- `<title>` → `Studio Panel v9.21`
- `.topbar-title` → `Studio Panel v9.21`

## PART 7 — Stopwatch in Diagnostics tab (DONE)

`functions/_shared/admin-renderer.js`:
- Added Stopwatch card at top of Diagnostics tab (before System Test).
- Start/Stop toggle button + Reset button.
- Displays `MM:SS.d` format, updating every 100ms.
- Pure client-side — no API calls, no new endpoints.
