# Prompt 61 — Resolver Hardening + Deterministic Errors

Context

The Campaign OS edge resolver is now working end‑to‑end:

/campaign/<alias>/<link>

KV resolution chain:

alias:<alias>        -> campaign
link:<campaign>:<id> -> destination URL

Example:

alias:test      -> demo
link:demo:test  -> https://example.com

The current system correctly performs redirects but error handling is ambiguous ("alias not found" can also mask missing links). We now harden the resolver and make errors deterministic.

---

Objective

Improve the resolver with the following changes:

1. Deterministic error separation
2. Safer path parsing
3. Basic request validation
4. Optional lightweight telemetry (console only)

No routing grammar changes. URL format stays:

/campaign/<alias>/<link>

---

Implementation

Modify:

functions/campaign/[[path]].js


1️⃣ Safe path parsing

Replace naive split logic with explicit validation.

Expected segments:

alias/link

Implementation concept:

const segments = path.split("/").filter(Boolean)

if (segments.length !== 2) {
  return new Response("invalid route", { status: 400 })
}

const [alias, linkId] = segments


2️⃣ Alias lookup

const campaign = await env.LINKHUB_SLUGS.get(`alias:${alias}`)

if (!campaign) {
  return new Response("alias not found", { status: 404 })
}


3️⃣ Link lookup

const destination = await env.LINKHUB_SLUGS.get(`link:${campaign}:${linkId}`)

if (!destination) {
  return new Response("link not found", { status: 404 })
}


4️⃣ Redirect

return Response.redirect(destination, 302)


5️⃣ Minimal telemetry

Add non‑blocking console logging:

console.log(JSON.stringify({
  event: "campaign_redirect",
  alias,
  campaign,
  linkId
}))

Do not add analytics storage yet.

## Implementation Summary (Prompt 61)

### Modified file: `functions/campaign/[[path]].js`

Four hardening changes over P60:

**1) Path parsing — `context.params.path` instead of `url.pathname`**
```js
// Before (P60): url.pathname split → discard parts[0] ("campaign")
// After  (P61): context.params.path already strips /campaign/ prefix
const path     = params?.path ?? "";
const segments = path.split("/").filter(Boolean);
if (segments.length !== 2) return new Response("invalid route", { status: 400 });
const [alias, linkId] = segments;
```
`[[path]]` catch-all injects `params.path = "alias/link-id"` directly — no need to skip the first segment.

**2) Deterministic error separation**
| Condition | P60 | P61 |
|---|---|---|
| path segments ≠ 2 | `"invalid redirect"` 400 | `"invalid route"` 400 |
| alias not in KV | `"alias not found"` 404 | `"alias not found"` 404 ✓ |
| link not in KV | `"link not found"` 404 | `"link not found"` 404 ✓ |

Both error paths now return distinct messages — no ambiguity.

**3) `Response.redirect()` instead of manual `new Response(null, { headers: { Location } })`**

**4) Console telemetry (non-blocking, no storage)**
```js
console.log(JSON.stringify({ event: "campaign_redirect", alias, campaign, linkId }))
```
Visible in Cloudflare Pages → Functions → Real-time logs.
