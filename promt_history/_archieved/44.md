

# Prompt 44 — Analytics Operator UI + Health Layer Stabilization

Goal: Harden the experiment health layer and prepare the analytics operator UI foundation. This prompt focuses only on fixes discovered during live testing and on infrastructure that must be stable before higher‑level experiment features are added.

---

# 1) Health Layer — Fixes Required Now

## 1.1 Adaptive sample size guard

Replace constant threshold:

MIN_SAMPLE = 50

with adaptive logic:

MIN_SAMPLE = max(50, total_exposures * 0.05)

Reason:

High‑traffic experiments should not validate winners using a fixed small threshold. The guard must scale with traffic to prevent premature decisions.

Expected behavior:

• small experiments → still protected by base threshold 50
• large experiments → required sample automatically increases

---

## 1.2 Correct inactive variant detection

Current rule:

variant_exposures == 0

Replace with:

total_exposures > 0 && variant_exposures == 0

Reason:

Avoid false warnings when an experiment has not yet received traffic.

Inactive warnings should only appear once the experiment has started receiving traffic.

---

## 1.3 Delay traffic imbalance detection

Traffic imbalance warnings should not run before minimum sample size is reached.

Current problem:

Low traffic experiments frequently trigger false imbalance warnings.

Fix:

Only evaluate imbalance when:

if total_exposures >= MIN_SAMPLE

Otherwise skip imbalance detection.

---

## 1.4 API consistency — expose effective winner

Current response:

winner: null
stored_winner: "variant"
state: DECIDED

Fix:

When state == DECIDED

winner = stored_winner

This ensures the API reflects the actual routing behavior.

---

## 1.5 Experiment metadata integrity

Ensure experiment creation sets:

created_at

Current behavior observed:

created_at: null

Fix:

Set timestamp during experiment creation for debugging, analytics timelines, and lifecycle management.

## Fix 1.1 — Adaptive sample size guard (`admin/experiments.js`)

Replaced fixed `MIN_SAMPLE = 50` with:

```js
var adaptiveMin = Math.max(MIN_SAMPLE, Math.floor(totalExp * 0.05));
```

Sample size guard now scales with traffic: small experiments still require ≥ 50 exposures per variant; large experiments require at least 5% of total traffic per variant before conclusions are trusted.

---

## Fix 1.2 — Inactive variant detection (`admin/experiments.js`)

Inactive check is now gated on `totalExp > 0`:

```js
if (totalExp > 0) {
  variants.forEach(function(v){
    if (v.exposures === 0) { /* warn */ }
  });
}
```

Suppresses false "Variant inactive" warnings on brand-new experiments that have not yet received any traffic.

---

## Fix 1.3 — Delayed imbalance detection (`admin/experiments.js`)

Imbalance check now only runs when enough data is present:

```js
if (!winnerRouting && totalExp >= adaptiveMin) { /* check */ }
```

Eliminates false `⚠ Traffic imbalance` warnings during the early low-traffic window when random variance naturally produces lopsided splits.

---

## Fix 1.4 — API consistency: effective winner (`api/experiments.js`)

Added `effectiveWinner` to the response:

```js
const effectiveWinner = effectiveState === "DECIDED"
  ? (effectiveStoredWinner ?? winnerSlug)
  : winnerSlug;
```

When `state === "DECIDED"` the `winner` field now always equals the `stored_winner` (the source of truth for routing). Callers no longer need to reconcile two separate fields.

---

## Fix 1.5 — Experiment `created_at` integrity (`api/ab.js`)

PUT handler reads existing config before writing:

```js
let existingConfig = null;
try {
  existingConfig = await env.ALIAS_REGISTRY.get(`ab_config:${alias}`, { type: "json" });
} catch (_) {}

const now = Math.floor(Date.now() / 1000);
const config = {
  variants:   body.variants,
  created_at: existingConfig?.created_at ?? now,
  updatedAt:  new Date().toISOString(),
};
```

- **Create** (no prior config): `created_at` stamped as unix timestamp at creation time.
- **Update** (config exists): `created_at` preserved unchanged — only `variants` and `updatedAt` change.

`created_at` is now always present in new configs, enabling analytics timelines and lifecycle management.

## Section 2 — Operator Breakdown card (`admin/experiments.js`)

New Layer 3.5 card inserted between the Conversion Rate chart and the Advanced Analytics section.

### `renderOperatorBreakdown(variants)`

- Hidden when `totalExp === 0` (no traffic yet)
- Shows one row per variant with columns: Variant | Source | Exposures | Clicks | Conv.
- Source column shows `(aggregate)` — a placeholder for the future per-source dimension
- Footer note: *"Source-level breakdown requires per-source instrumentation."*

### CSS added

`.op-table`, `.op-table th`, `.op-table td`, `.op-source`, `.op-note` (with dark-mode variant)

### Design decisions

- **Foundation pattern**: the table structure (variant × source) is fully in place and ready to receive per-source rows once `utm_source`-keyed counters are instrumented in a future prompt. No structural rework will be needed.
- **Aggregate row today**: showing aggregate data under `(aggregate)` source label is more useful than an empty card — operators can immediately see if per-variant totals look correct.
- **Hidden when no data**: same zero-traffic hide rule as the Distribution card — keeps the UI clean before experiments start.

---

## Design decisions (cross-cutting)

- **`adaptiveMin` scoped locally in `renderHealth`**: the adaptive threshold is recomputed per dashboard load; no global mutation of `MIN_SAMPLE` (chart threshold stays at 30, health threshold stays at 50 base).
- **`effectiveWinner` does not change routing**: it is a pure response-layer normalization. Routing continues to use `abConfig.winner` from KV directly.
- **`created_at` as unix integer**: consistent with `decided_at` and `archived_at` already used in the lifecycle system.
