

# Prompt 51 — Experiment Router Extraction (Production Engine Step 1)

You are working inside the Campaign OS codebase that powers the Cloudflare Workers deployment for the Nilüfer Ormanlı campaign routing system.

Your task is to perform a **safe router extraction refactor**.

IMPORTANT CONSTRAINTS:

- This is a **refactor only**.
- **No behavior change is allowed.**
- Public URLs, routing outcomes, cookies, counters and experiment behavior **must remain identical**.
- The goal is only to **separate responsibilities** so the experiment system becomes maintainable.

---

# Current Problem

The current routing file (likely `[[path]].js`) mixes several responsibilities:

1. Alias routing
2. Experiment assignment
3. Cookie stickiness
4. Exposure counter writing
5. Hub page rendering
6. Final redirect resolution

This makes future work (exposure tokens, integrity protection, bandit control) risky.

We want to extract **Experiment Router logic** into a dedicated module.

---

# Target Architecture

After the refactor the routing pipeline should conceptually look like:

```
incoming request
      ↓
alias resolver
      ↓
experiment router
      ↓
final slug resolution
      ↓
hub render or redirect
```

Experiment logic must live in its own module.

---

# New Module

Create a module:

```
/lib/experiment-router.js
```

This module must expose a single function:

```
resolveExperimentVariant(request, experimentConfig, env)
```

It should return:

```
{
  finalSlug,
  variantId,
  isNewAssignment,
  cookieToSet
}
```

Where:

- `finalSlug` = slug that will actually be served
- `variantId` = selected variant
- `isNewAssignment` = true if cookie did not exist
- `cookieToSet` = cookie header value if assignment happened

---

# Logic That Must Move Into experiment-router

Move these responsibilities out of the main routing file:

### Variant selection

- weight-based routing
- cf-ray hashing logic
- bucket selection

### Cookie stickiness

If cookie exists → use stored variant.

If cookie does not exist → perform assignment and return cookie.

### Experiment state gating

Routing must respect experiment states:

```
RUNNING  → assign + count exposure
PAUSED   → serve existing cookie only, no new assignment
DECIDED  → always route to winning variant
ARCHIVED → bypass experiment entirely
```

### Exposure counting

Exposure increments must remain exactly the same call:

```
incrementExpCounter(env, alias, finalSlug, "exposure")
```

Only when:

- experiment is RUNNING
- variant was served

## Implementation Summary

### Files Created

**`functions/lib/experiment-router.js`** — new dedicated experiment routing module

Exports one function: `resolveExperimentVariant(request, experimentConfig, env, opts)`

Moved into this module from `[[path]].js`:
- Lifecycle state gating (DRAFT / RUNNING / PAUSED / DECIDED / ARCHIVED)
- Cookie-based sticky bucketing (`readCookie`, `buildSetCookie`)
- Deterministic weighted bucket selection (`selectABVariant`)
- Exposure counter scheduling (`incrementExpCounter`) — returned as `counterPromise`
- `AB_SELECTED` ops telemetry (`emitOps`)

Return shape:
```js
{
  finalSlug:       string,          // slug to serve
  variantId:       string,          // = finalSlug (slug is variant ID in this system)
  isNewAssignment: boolean,         // true → new cookie must be set
  cookieToSet:     string | null,   // pre-built Set-Cookie header value, or null
  abActive:        boolean,         // false only for DRAFT; true for all active states
  counterPromise:  Promise | null,  // pass to context.waitUntil(); null for PAUSED/DECIDED/ARCHIVED/DRAFT
}
```

State routing is identical to the previous inline implementation:

| State    | finalSlug       | Cookie        | Counter   | abActive |
|----------|-----------------|---------------|-----------|----------|
| DRAFT    | canonicalSlug   | —             | —         | false    |
| RUNNING  | variant (sticky)| set if new    | increment | true     |
| PAUSED   | variant (sticky)| set if new    | frozen    | true     |
| DECIDED  | winner slug     | —             | —         | true     |
| ARCHIVED | winner slug     | —             | —         | true     |

### Files Modified

A/B routing block replaced with a clean 18-line call:
```js
const abConfig = await loadABConfig(alias, env);

if (abConfig) {
  expResult = resolveExperimentVariant(request, abConfig, env, {
    alias, canonicalSlug, requestId, modifier,
  });
  finalSlug = expResult.finalSlug;
  abActive  = expResult.abActive;
  if (abActive) {
    utmExperiment = alias;
    utmVariant    = expResult.finalSlug;
  }
  if (expResult.counterPromise) {
    context.waitUntil(expResult.counterPromise);
  }
}
```

Response header block:
- `newAssignment` → `expResult?.isNewAssignment` (Cache-Control guard)
- `buildSetCookie(...)` inline → `expResult?.cookieToSet` (pre-built in module)

File size: 413 → 355 lines (−58 lines)

### Behavior Unchanged

All of the following remain identical:
- Cookie naming: `exp_<alias>`
- Cookie TTL: 30 days (`Max-Age=2592000`), `Path=/; SameSite=Lax; Secure`
- Exposure counter key format: `exp:<alias>:<slug>:exposure:<shard>`
- Counter increment gating: RUNNING only (PAUSED frozen, DECIDED/ARCHIVED/DRAFT skipped)
- Sticky bucketing: cookie checked before `selectABVariant()`
- Variant selection algorithm: last-8-hex of cf-ray → `% 100` → cumulative weight walk
- `AB_SELECTED` telemetry payload: alias, modifier, canonical_slug, campaign, sticky, state
- `TRAFFIC_MEMORY` telemetry: unchanged, still emitted in `[[path]].js` after module call
- UTM fields: `utm_experiment`, `utm_variant` set via `abActive` flag
- DRAFT passthrough: canonical slug, no UTMs, no cookie, no counter
- DECIDED / ARCHIVED winner routing: winner served, no new cookie, no counter
