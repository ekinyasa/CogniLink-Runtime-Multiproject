Prompt 69-3 — Automatic Router Compile After Experiment Changes

During testing we discovered a critical workflow issue in the experimentation system.

Current behavior:

• Creating an experiment works
• Activating an experiment works
• Saving A/B config in Routing works

BUT the public alias URL does NOT become active until the operator manually presses:

Routing → “Compile Now”

Example:

Create experiment:

alias: sim3AB
campaign: sim-3
variants: sim-3-igbio / sim-3-yt

After activation:

https://links.niluferormanli.studio/sim3AB → NOT FOUND

After manual compile:

Routing → Compile Now

Then:

https://links.niluferormanli.studio/sim3AB → works

This is unacceptable for operator workflow. The system must compile automatically whenever routing state changes.

⸻

Required Fix

The router compilation step must run automatically after any operation that changes routing state.

Trigger auto-compile after:
	1.	Creating an experiment
	2.	Activating an experiment
	3.	Saving A/B config from Routing tab
	4.	Rebalancing traffic weights
	5.	Promoting a winner

Implementation rule:

Wherever routing configuration is written (alias registry, AB config, experiment state), trigger the same compile routine currently executed by the “Compile Now” button.

Pseudo behavior:

writeRoutingConfig()
→ compileRouter()

Do NOT require manual compile from the operator.

⸻

Safety Rules
	1.	Compile must run asynchronously so the UI does not freeze.
	2.	Compile must only run once per mutation (no compile loops).
	3.	Existing “Compile Now” button must remain for manual use.

⸻

Verification Criteria

After the fix:

Create experiment → Activate

Immediately after activation:

https://links.niluferormanli.studio/

must resolve without requiring manual compile.

The routing system should behave as if compile was pressed automatically.

⸻

Do NOT change

• public URL grammar
• experiment schema
• campaign/slug registry structure

Only automate the compile trigger.
