# Prompt 64 — Production Conversion Ingestion + Experiment Telemetry Stabilization

Context:
We have a working Campaign OS running on Cloudflare Workers + KV + Analytics Engine.
The following parts already exist and must NOT be broken:

- alias router
- /c/<slug> canonical campaign links
- A/B experiment router
- telemetry endpoint `/t`
- analytics engine dataset
- KV counters
- admin experiment panel

Traffic routing and click telemetry are working in production.

What is missing is **reliable conversion ingestion** and **stable experiment attribution**.

The goal of this prompt is to implement a production‑safe conversion pipeline without changing the existing routing grammar.

Important constraints:

1. Do NOT change public URL grammar.
2. Do NOT change `/alias` or `/c/<slug>` behavior.
3. Do NOT break existing telemetry keys.
4. All changes must be additive and backward compatible.


--------------------------------------------------
TASK 1 — Variant Cookie Persistence
--------------------------------------------------

When the experiment router assigns a variant, persist it in a cookie so downstream systems (Kartra checkout) can report conversions.

On experiment assignment:

Write cookie:

```
cos_variant=<variant>
```

Properties:

- path=/
- max-age=86400
- sameSite=Lax

Example value:

```
cos_variant=63-campaign-igbio
```

Also store experiment alias:

```
cos_exp=63-campaign
```

These cookies allow downstream pages to call the conversion endpoint.


--------------------------------------------------
TASK 2 — Conversion Ingestion Endpoint
--------------------------------------------------

The telemetry endpoint `/t` already exists and accepts events.

Ensure it supports:

```
/t?e=conversion&exp=<experiment>&v=<variant>
```

Example:

```
/t?e=conversion&exp=63-campaign&v=63-campaign-igbio
```

When this endpoint is called:

Write counters:

KV key:

```
telemetry:exp:<experiment>:<variant>:conversion
```

Increment counter.

Also write Analytics Engine event with fields:

```
event = conversion
experiment
variant
alias (if available)
link_id (if available)
user_agent_hash
```


--------------------------------------------------
TASK 3 — Conversion Deduplication
--------------------------------------------------

Conversions can be triggered multiple times by reloads or Kartra scripts.

Implement lightweight dedup using:

```
hash(user-agent)
```

Create key:

```
dedup:conv:<experiment>:<variant>:<ua_hash>
```

TTL:

```
30 minutes
```

If key exists:

ignore duplicate conversion.

If not:

store key and accept conversion.


--------------------------------------------------
TASK 4 — Conversion Test Endpoint
--------------------------------------------------

Create a simple internal endpoint for testing conversions without waiting for real purchases.

Route:

```
/conv-test
```

Behavior:

Redirect to:

```
/t?e=conversion
```

If cookies exist:

```
cos_exp
cos_variant
```

Automatically populate:

```
exp=<cos_exp>
v=<cos_variant>
```

This allows testing conversion telemetry directly from the browser.


--------------------------------------------------
TASK 5 — Experiment Telemetry Consistency
--------------------------------------------------

Ensure the experiment analytics panel reads the same KV keys written by `/t`.

Conversion key format MUST be:

```
telemetry:exp:<experiment>:<variant>:conversion
```

Do not introduce new naming schemes.

Verify panel queries match this format.


--------------------------------------------------
TASK 6 — No Changes to Routing
--------------------------------------------------

Do NOT change:

```
/alias
/c/<slug>
/r redirect system
```

Conversion ingestion must be independent from routing.

### T1 — Variant cookie persistence

**`functions/lib/experiment-router.js`** — two new cookies built after `cookieToSet`:

```js
const cosVariantCookie = buildSetCookie("cos_variant", finalSlug, { maxAge: 86400 });
const cosExpCookie     = buildSetCookie("cos_exp",     alias,      { maxAge: 86400 });
```

Returned in the result object alongside `cookieToSet`. Set on every active-experiment request (not just new assignments) so visitors who arrived before P64 also receive cookies on their next visit.

**`functions/[[path]].js`** — cookie section extended:

```js
if (expResult?.cookieToSet)      resHeaders.append("Set-Cookie", expResult.cookieToSet);
if (expResult?.cosVariantCookie) resHeaders.append("Set-Cookie", expResult.cosVariantCookie);
if (expResult?.cosExpCookie)     resHeaders.append("Set-Cookie", expResult.cosExpCookie);
```

### T2+T3 — `/t` upgrade (UA hash + dedup + sharded counter)

**`functions/t.js`** — key additions:

1. **Optional query params** — `alias` and `link_id` parsed and sanitized (empty string if absent).

2. **UA hash** (`computeUaHash`):
   ```js
   async function computeUaHash(userAgent) {
     const encoded = new TextEncoder().encode(userAgent || "");
     const hashBuf = await crypto.subtle.digest("SHA-256", encoded);
     return Array.from(new Uint8Array(hashBuf).slice(0, 8))
       .map(b => b.toString(16).padStart(2, "0")).join("");
   }
   ```
   16-char hex; first 8 bytes of SHA-256 of User-Agent string. Non-PII.

3. **Conversion dedup** (conversion events only):
   ```
   dedup:conv:<exp>:<v>:<ua_hash>   TTL 1800s (30 min)
   ```
   If key exists → `respond()` immediately (silent discard).
   If not exists → write key with `expirationTtl: 1800`, proceed.

4. **Sharded counter bridge** (conversion events only):
   ```js
   context.waitUntil(incrementExpCounter(env, exp, v, "conversion"));
   ```
   Writes `exp:<exp>:<v>:conversion:<shard>` — the key space read by the admin panel via `getExpCounters()`. Bridges the gap between `/t` conversion events and the panel dashboard.

5. **Enriched AE payload**:
   ```js
   env.TELEMETRY_EVENTS.writeDataPoint({
     blobs:   [exp, v, e, alias, linkId, uaHash],
     doubles: [Date.now()],
   });
   ```

### T4 — Conversion test endpoint

**`functions/conv-test.js`** (new):

```
GET /conv-test
```

Reads `cos_exp` and `cos_variant` cookies; redirects to `/t?e=conversion&exp=<cos_exp>&v=<cos_variant>`.
If cookies are missing, redirects to `/t?e=conversion` (which `/t` will silently drop).

Test flow:
1. Open experiment alias URL → `cos_exp` + `cos_variant` written
2. Open `/conv-test` → 302 → `/t?e=conversion&exp=…&v=…`
3. `/t` records conversion → panel counter increments

### T5 — Key-space consistency

KV counter key spaces:

| Key pattern | Written by | Read by |
|---|---|---|
| `telemetry:exp:<exp>:<v>:<event>` | `/t` (all events) | ad-hoc / direct KV inspection |
| `exp:<exp>:<v>:conversion:<shard>` | `/t` (conversion only, P64) + edge router | admin panel via `getExpCounters()` |
| `dedup:conv:<exp>:<v>:<ua_hash>` | `/t` (conversion only) | `/t` dedup gate |

The `telemetry:exp:*` counter format is preserved unchanged. The new `incrementExpCounter` call for conversion events is an additive write to the **existing** sharded `exp:*` key format — no new naming schemes introduced.

`/alias`, `/c/<slug>`, and the campaign redirect router are not modified.
Conversion ingestion is fully independent of routing.
