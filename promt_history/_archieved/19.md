Goal

Stabilize the diagnostics layer, fix the remaining test and analytics issues discovered during Prompt 18 validation, and introduce the first product-level capability that converts Campaign OS from a single-project tool into a micro-SaaS platform.

Important rules

• Do NOT modify router grammar.

--------------------------------------------------

PART 1 — Fix AE Event Collapse (Click Timing)

Manual validation currently fires the sequence:

/alias
/alias
/alias/offer
/alias/vsl

These events are currently fired within the same millisecond which occasionally causes Analytics Engine to collapse events.

Update the test runner click sequence:

/alias
wait 150ms
/alias
wait 150ms
/alias/offer
wait 150ms
/alias/vsl

This guarantees deterministic ingestion.

--------------------------------------------------

PART 2 — Correct Slug Handling in Diagnostics

The current diagnostics UI reconstructs slug using:

fixture.campaign + "-igbio"

This must be removed.

Backend system test responses must now return:

fixture: {
  alias,
  campaign,
  slug
}

Diagnostics UI must display slug directly from response.

--------------------------------------------------

PART 3 — Fix Analytics Slug Filter

The analytics “Show test campaigns” filter currently fails for the slug table.

Correct the filter behavior:

When filter OFF:
hide rows where campaign OR alias OR slug startsWith("test-")

When filter ON:
show ONLY rows where campaign OR alias OR slug startsWith("test-")

Filtering must apply consistently to:

Campaign table
Alias table
Slug table
Recent events table

--------------------------------------------------

PART 4 — Fix Admin Verify Routing

The endpoint

/admin/verify/<alias>?token=ADMIN_TOKEN

must work correctly under Cloudflare Pages routing.

Verify:

functions/admin/verify/[alias].js

is correctly mapped.

Expected behavior:

Valid token → hub rendered with overlay
Invalid token → 401
Alias archived → diagnostic message (200)

--------------------------------------------------

PART 5 — Improve Link Validation States

Extend validator state mapping.

Possible states:

VALID
SUSPICIOUS
BROKEN

UI must display:

✔ VALID
⚠ SUSPICIOUS
✖ BROKEN

Rules:

VALID → HTTP 200 + correct domain
SUSPICIOUS → unexpected redirect chain or domain mismatch
BROKEN → network error, redirect loop, or unreachable URL

--------------------------------------------------

PART 6 — Fix Background Self-Test Authentication

Ensure the endpoint:

/api/admin/background-test

accepts Authorization header:

Authorization: Bearer ADMIN_TOKEN

Return proper error codes:

401 Unauthorized → missing or invalid token
500 → internal execution error

Store result:

LINKHUB_CONFIG["_bg_test_last"]

with fields:

{
 ok,
 timestamp,
 duration_ms,
 fixture
}

Add optional workspace support.

Workspace acts as a namespace:

workspace_id
campaigns
analytics
routing
diagnostics

Default workspace:

"default"

Router behavior remains unchanged.

Workspace only affects:

admin panel
analytics queries
campaign registry

Registry key structure:

route:{workspace}:{alias}

Analytics fields must include workspace:

workspace
campaign
alias
slug

If workspace not provided:

fallback to "default"

PART 8 — Admin Workspace Selector

Admin panel must include workspace selector.

Example:

Workspace:
[ default ▼ ]

Changing workspace filters:

campaign registry
analytics
diagnostics

After Prompt 19:

Campaign OS becomes:

• fully deterministic testable system

Conclusion:
**The AE spacing change may be present, but the real validation failure is not solved.**

### 3. Background self-test is not operationally acceptable
UI still reports generic failure:

Although request authorization header is present in the browser request, the operator is not given meaningful failure stage or reason.

**Prompt 19 claim "Background Self-Test Authentication ✓" is not enough.**

Conclusion:
**Prompt 19 analytics filtering fix is incomplete.**
All-table consistency was not achieved.

Conclusion:
