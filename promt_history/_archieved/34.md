# SECTION 3 — Conversion Rate Calculation

Extend experiment aggregation endpoint:

GET /api/experiments?alias=<alias>

Add fields:

{
 variant:"cd26-test-yt",
 exposures:398,
 clicks:112,
 conversions:37,
 ctr:0.281,
 conversion_rate:0.093
}

Definitions:

ctr = clicks / exposures
conversion_rate = conversions / exposures

(We use exposure as the denominator for now to keep the model simple.)

# SECTION 4 — Winner Detection

Add simple winner logic inside aggregation endpoint.

Rules:

1. Minimum exposure threshold

Each variant must have at least:

MIN_EXPOSURE = 30

2. Compare conversion_rate

Variant with highest conversion_rate becomes provisional winner.

3. If difference between best and baseline is greater than:

WINNER_THRESHOLD = 0.05 (5%)

then mark variant as:

"winner":true

Example response:

{
 experiment:"abtest",
 winner:"cd26-test-yt",
 variants:[
  {
   slug:"cd26-test-igbio",
   exposures:120,
   conversions:9,
   conversion_rate:0.075
  },
  {
   slug:"cd26-test-yt",
   exposures:115,
   conversions:15,
   conversion_rate:0.130,
   winner:true
  }
 ]
}

This is NOT statistical significance.

It is only a heuristic indicator.

1. Conversion Counter KV Schema

Namespace: ALIAS_REGISTRY (same as exposure/click counters — no new binding)
Key format: exp:<alias>:<slug>:conversion
Value:      plain text integer string (e.g. "37")

Examples:
  exp:abtest:cd26-test-igbio:conversion  →  "9"
  exp:abtest:cd26-test-yt:conversion     →  "15"

exp-counter.js getExpCounters() now reads all three counter types per
variant in a single Promise.all (3×N parallel KV reads), returning:
  { slug, exposures, clicks, conversions, ctr, conversion_rate }

incrementExpCounter() is unchanged — already accepts any type string.

──────────────────────────────────────────────────────────────────

2. Conversion API Behavior

POST /api/convert
No authentication — public endpoint (like POST /api/event).
CORS headers included (Access-Control-Allow-Origin: *) so landing
pages on any domain can call it from the browser.
OPTIONS preflight handled.

Request body: { event, experiment, variant }
  • event      — event name string (logged only, not stored)
  • experiment — A/B alias (validated via validateAlias + loadABConfig)
  • variant    — variant slug (must appear in abConfig.variants[].slug)

Validation flow:
  1. Parse JSON
  2. validateAlias(expAlias) — format guard, prevents KV key injection
  3. loadABConfig(expAlias, env) — 404 if alias has no A/B config
  4. validSlugs.includes(expVariant) — 404 if variant not in config

On success:
  context.waitUntil(incrementExpCounter(env, expAlias, expVariant, "conversion"))
  Returns 204 (like /api/event — non-blocking to landing page navigation)

Snippet for landing/checkout pages:
  var exp = new URLSearchParams(location.search).get("utm_experiment") || "";
  var vrn = new URLSearchParams(location.search).get("utm_variant")    || "";
  if (exp && vrn) fetch("/api/convert", {
    method: "POST", headers: {"Content-Type":"application/json"},
    body: JSON.stringify({ event:"signup", experiment:exp, variant:vrn })
  });

──────────────────────────────────────────────────────────────────

3. Aggregation Math

GET /api/experiments?alias= (experiments.js) now computes:

  ctr             = clicks / exposures            (unchanged from Prompt 33)
  conversion_rate = conversions / exposures       (NEW — uses exposure as denominator)
  lift            = (variantCTR - baselineCTR) / baselineCTR   (unchanged)
  conversion_lift = (variantConvR - baselineConvR) / baselineConvR  (NEW)

All rates rounded to 4 decimal places (e.g. 0.1307 = 13.07%).
lift and conversion_lift are 0 for baseline variant, null when the
baseline denominator is 0 (division by zero guard).

──────────────────────────────────────────────────────────────────

4. Winner Detection Rules

Constants:
  MIN_EXPOSURE     = 30    — minimum exposures per variant to evaluate
  WINNER_THRESHOLD = 0.05  — minimum absolute conversion_rate advantage

Algorithm:
  1. If any variant has exposures < MIN_EXPOSURE → no winner declared
  2. Find variant with highest conversion_rate (excluding baseline)
  3. If (best.conversion_rate - baseline.conversion_rate) > WINNER_THRESHOLD
     AND best is not baseline → winnerSlug = best.slug
  4. Otherwise → winner: null

Response includes:
  { experiment, winner: "cd26-test-yt" | null, variants: [...] }
  Each winning variant also gets { winner: true } in its object.

This is a heuristic indicator, NOT statistical significance.
It requires real-world data accumulation before firing.

──────────────────────────────────────────────────────────────────
