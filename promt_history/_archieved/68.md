--------------------------------------------------
SECTION 1 — Fix Campaign-Scoped Slug Filtering
--------------------------------------------------

Problem
The Experiments page now tries to filter slugs by campaign, but the variant selector cannot populate after selecting a campaign.

Example broken state:

`No slugs for "abrand45"`

Likely cause
The selector is assuming `slug.startsWith(campaign)` is always true, but this is not valid for all existing campaign/slug naming patterns.

Examples:
- campaign: `ab-rand-45`
- experiment alias: `abrand45`
- slug: `ab-rand-45-igbio`

The filtering logic must use the campaign’s actual slug membership, not fragile prefix assumptions.

Required fix
The variant selector on the Experiments page must load slugs using the same source of truth as the routing/admin layer.

Implementation requirements
1. When a campaign is selected, fetch the actual slugs belonging to that campaign from the existing admin API or storage source
2. Do NOT rely solely on `slug.startsWith(campaign)`
3. Keep the selector limited to slugs from the selected campaign only
4. The selector must successfully populate for existing campaigns like:
   - `ab-rand-45`
   - `a65-ab-campaign`
   - similar legacy naming patterns

Expected result
After choosing a campaign, the two variant dropdowns should populate with only that campaign’s valid slugs.

Requirements
1. Must remain backward compatible with experiments that do not define strategy/epsilon
2. Default behavior for old configs stays unchanged
3. Epsilon must be validated to range `0 <= epsilon <= 1`
4. Strategy must be optional

### Section-by-section decisions

- **S1 fix**: Root cause — `loadCampaigns()` was calling `/api/admin/aliases` (alias names like `abrand45`) but slug records use `campaign: "ab-rand-45"` (the full campaign name). Fix: new `/api/admin/campaigns` endpoint returning LINKHUB_CAMPAIGNS names + value-based slug filter on the backend (`record.campaign === campaign`).

- **S2 add variant**: Create form replaced with dynamic variant-row system. Each row has a slug select + weight input. "Add Variant" appends rows (max 10). "×" remove on rows 2+ (hidden when only 2 rows). Live weight total with green/red feedback.

- **S3 rebalance**: "Rebalance Traffic" card shown for RUNNING/PAUSED states. Uses existing `PUT /api/ab` with updated weights + preserved `strategy`/`epsilon`.

- **S4 epsilon-greedy**: `selectABVariant` — uses hex chars `[-12..-8]` for explore/exploit check (0–999, `< round(eps*1000)` → explore) then `bucket % variants.length` for uniform random variant. Exploitation falls through to weighted routing. "Experiment Settings" card in UI; saves via `PUT /api/ab`.

- **S5 winner promotion**: `POST /api/experiment/decide` sets `winner` + `state=DECIDED` + `decided_at`, invalidates cache. "♛ Set Winner" button per variant row (RUNNING/PAUSED only). After decide, experiment reloads in DECIDED state and existing "Promote Winner" button becomes active.

- **Routing tab exp selector**: `loadAbAliases()` now makes two separate fetches — A/B Config selector still uses `/api/admin/aliases`; Experiment Results selector uses `/api/admin/experiments` (shows `alias — STATE`).

- **ws-selector**: `.topbar>#ws-selector{display:none!important}` added to admin-renderer CSS.
