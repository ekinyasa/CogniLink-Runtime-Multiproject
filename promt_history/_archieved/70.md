PROMPT 70 — Conversion Attribution Completion

Goal
The experimentation system is already validated for:
• traffic routing
• exposure counting
• click telemetry
• conversion telemetry
• experiment analytics

The missing piece is **reliable conversion attribution** tied to the original variant assignment.

We must ensure conversions are attributed to the **same variant the user originally received**, even when the conversion happens later (for example on a thank‑you page).

---

Task 1 — Persist assigned variant in cookie

When a variant is resolved in the router:

• store experiment alias
• store variant slug
• store timestamp

Cookie example:

experiment_prf = {
  variant: "proove-ttbio",
  exp: "prf",
  ts: 1712345678
}

Requirements

• cookie TTL: 7 days
• httpOnly: false (frontend must read it)
• sameSite: Lax
• path: /

Do not overwrite if already present.

This guarantees **sticky attribution**.

---

Task 2 — Variant resolve helper

Create helper:

resolveVariantFromCookie(alias)

Behavior:

1. read cookie experiment_<alias>
2. validate structure
3. return variant slug
4. if missing → return null

Used by conversion endpoints.

---

Task 3 — Conversion endpoint fallback logic

Modify

/api/experiment/conversion

Current behavior requires:

{
  alias: "...",
  variant: "..."
}

New behavior:

If variant is missing:

1. attempt resolveVariantFromCookie(alias)
2. if found → attribute conversion
3. if not → ignore request

This allows conversion calls from **client pages without variant knowledge**.

---

Task 4 — Thank‑you page conversion ping

Provide lightweight JS snippet that fires conversion automatically.

Example:

<script>
fetch("/api/experiment/conversion",{
  method:"POST",
  headers:{ "Content-Type":"application/json" },
  body:JSON.stringify({ alias:"prf" }),
  keepalive:true
});
</script>

The server will resolve the variant using the cookie.

Important:

• must not block page rendering
• must tolerate network errors

---

Task 5 — Attribution validation log

Add debug log (development only):

EXPERIMENT CONVERSION
alias: prf
variant: proove-ttbio
source: cookie|payload

This helps diagnose attribution mismatches.

---

Task 6 — Analytics verification endpoint

Add temporary endpoint:

/api/experiment/debug/:alias

Return:

• exposures
• clicks
• conversions
• conversion_rate
• lift
• variant weights

Purpose: quick verification during testing.

Remove or guard behind admin auth later.

---

Expected Result

After this change:

User flow becomes:

visitor
→ router assigns variant
→ cookie stores assignment
→ visitor clicks link
→ visitor converts later
→ thank‑you page fires conversion ping
→ server resolves variant from cookie
→ conversion attributed correctly

This closes the full attribution loop.

## Implementation Summary

### Task 1 — Attribution cookie (`experiment-router.js` + `[[path]].js`)

Cookie name: `experiment_<alias>`
Value: `encodeURIComponent(JSON.stringify({ variant, exp, ts }))` — URI-encoded so JSON is safe in cookie header.
Max-Age: 604800 (7 days).  SameSite: Lax.  httpOnly: false (frontend-readable).
Do-not-overwrite: `readCookie(request, "experiment_" + alias)` checked before building — returns `null` (no Set-Cookie header) when already present.
Wired in `[[path]].js` alongside the existing `cos_variant` / `cos_exp` cookies.

### Task 2 — `resolveVariantFromCookie` helper (`conversion.js`)

```js
function resolveVariantFromCookie(request, alias) {
  const raw = readCookie(request, "experiment_" + alias);
  if (!raw) return null;
  try {
    const data = JSON.parse(decodeURIComponent(raw));
    if (typeof data.variant === "string" && data.variant) return data.variant;
  } catch (_) {}
  return null;
}
```

### Task 3 — Conversion endpoint updated (`conversion.js`)

`variant` is now optional.  Resolution priority:
1. `body.variant` (explicit payload)
2. `resolveVariantFromCookie(request, alias)` (attribution cookie)
3. Return `{ ok: false, reason: "no_variant" }` — silent 200, no counter written.

`source: "payload" | "cookie"` field added to the success response for tracing.

### Task 4 — Thank-you page snippet

```html
<script>
fetch("/api/experiment/conversion", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ alias: "prf" }),  // variant resolved from cookie server-side
  keepalive: true
}).catch(function(){});  // never block page; silently swallow errors
</script>
```

### Task 5 — Attribution debug log (`conversion.js`)

```js
console.log("[conversion]", JSON.stringify({ alias, variant, source }));
```

Emitted after every successful attribution. `source` distinguishes `"payload"` vs `"cookie"`.

### Task 6 — Debug endpoint (`/api/experiment/debug/[alias].js`)

New file: `functions/api/experiment/debug/[alias].js`
Auth: Bearer token required.
Returns:
```json
{
  "alias": "prf",
  "state": "RUNNING",
  "strategy": null,
  "variants": [
    { "slug": "proove-ttbio", "weight": 80, "exposures": 1234, "clicks": 456,
      "conversions": 23, "ctr": 0.3693, "conversion_rate": 0.0186, "lift": null },
    { "slug": "proove-igbio", "weight": 20, "exposures": 321, "clicks": 134,
      "conversions": 8,  "ctr": 0.4173, "conversion_rate": 0.0249, "lift": 33.87 }
  ]
}
```
`lift` = `((variant_cvr / control_cvr) - 1) × 100`.  `null` for the first variant (control) and when control has zero conversions.

### Stopwatch click reliability (`admin-renderer.js`)

CSS safeguard added:
```css
#sw-display * { pointer-events: none; }
```
JS listener updated to use `ev.currentTarget` explicitly (`void ev.currentTarget` binding guard).
Both layers ensure clicks on any descendant text always reach the button handler.
