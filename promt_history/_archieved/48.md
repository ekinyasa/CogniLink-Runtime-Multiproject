# Prompt 48 — Deterministic Router + Bandit Learning Separation

Goal: remove the architectural conflict between router-time Thompson sampling and bandit-update weight generation.

Current system has two competing decision models:

1. `bandit-update` computes and writes new `weight` values
2. `ab-router` still performs Thompson sampling if `alpha/beta` exist

This makes routing nondeterministic and causes the router to ignore updated weights.

This prompt separates responsibilities cleanly:

- bandit-update = learning engine
- router = deterministic weighted traffic allocator

---

## 1. Remove Thompson Sampling From Router

`ab-router.js` must no longer perform Thompson sampling during request routing.

Current problematic behavior:

- if variants contain `alpha/beta`
- router samples dynamically
- written `weight` values are ignored

This branch must be removed.

### Required router behavior

The router must always use deterministic weighted bucket routing:

```js
const hex    = String(requestId || "").replace(/[^0-9a-f]/gi, "").slice(-8) || "0";
const bucket = parseInt(hex, 16) % 100;

let cumulative = 0;
for (const variant of config.variants) {
  cumulative += variant.weight;
  if (bucket < cumulative) return variant.slug;
}
return config.variants[config.variants.length - 1].slug;
```

---

The router must not depend on `alpha/beta` at all.

---

## 2. Bandit Update Becomes the Only Learning Engine

`bandit-update.js` remains responsible for learning from traffic and conversions.

Responsibilities:

- read exposures + conversions
- compute posterior:
  - `alpha = conversions + 1`
  - `beta = exposures - conversions + 1`
- run Thompson sampling
- convert result into updated integer `weight` values
- write updated weights back to experiment config

### Important change

Do not use a single Thompson draw to compute weights.

Single-draw sampling is too noisy and unstable.

Instead compute average Thompson score using multiple draws.

### Required behavior

Use N repeated draws (recommended: `draws = 200`) and average them:

```js
const avgSamples = variants.map((v) => {
  let sum = 0;
  for (let i = 0; i < draws; i++) {
    sum += betaSample(alpha, beta);
  }
  return sum / draws;
});
```

Then convert averaged scores into final integer weights.

This produces stable exploration/exploitation behavior.

---

## 3. Keep Exploration Floor

Bandit-generated weights must continue to enforce a hard exploration floor.

Example:

- minimum 5%
- maximum 95%

No variant may be reduced below the configured floor.

This preserves exploration even after a strong winner emerges.

---

## 4. Keep Alpha/Beta as Metadata Only

`alpha` and `beta` may remain in experiment config for:

- admin UI inspection
- debugging
- operator visibility

But they must NOT affect routing.

Routing authority must be:

```
variant.weight
```

only.

---

## 5. Expected Result

After this prompt:

- router becomes deterministic again
- config `weight` becomes the single routing truth
- bandit-update remains the sole learning mechanism
- routing becomes reproducible and debuggable
- bandit still shifts traffic toward better-performing variants automatically

---

## 6. Safety Requirements

Do NOT change:

- URL structure
- experiment alias format
- counter key format
- admin experiment APIs
- attribution parameters

This prompt only separates learning from routing.

---

## 7. Success Criteria

After running `Update Bandit Weights`:

- experiment config weight changes
- router traffic distribution gradually follows those weights
- no routing branch depends on `alpha/beta`
- admin panel weights match actual routing logic

---


### Architecture After Prompt 48

| Concern | Before P48 | After P48 |
|---------|-----------|-----------|
| Routing | Hybrid: deterministic OR Thompson at request time | Always deterministic (weight-only) |
| Learning | bandit-update + router both ran Thompson | bandit-update only |
| alpha/beta | Router input (triggered Thompson mode) | Metadata only (admin UI / debugging) |
| Weight stability | Single draw per bandit-update call | N=200 averaged draws per call |
| Reproducibility | Nondeterministic when alpha/beta present | Deterministic: requestId + weights → reproducible |
| Admin panel | Showed weights that weren't used | Shows weights that drive actual routing |

### Constraints Met

- No URL changes
- No counter key changes
- No admin experiment API changes
- No attribution parameter changes
- `bandit-update.js` call signature unchanged (passes `variants` to `computeBanditWeights` — new `draws` param defaults to 200)
- Backward compat: existing configs without alpha/beta still route correctly (weight-only routing was always the fallback)
