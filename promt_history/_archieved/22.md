## SECTION A — Mevcut Mimari ve Execution Flow

### 1. Workspace Logic

**Nerede saklanır:** `workspace` string alanı olarak her `LINKHUB_CAMPAIGNS` KV record'unda bulunur (örn. `"default"`, `"prod"`, `"test"`). Slug record'larında workspace alanı **yoktur** — slug'ın workspace'i dolaylı olarak bağlı olduğu campaign'den gelir.

**Ne tetikler:** `POST /api/campaign` oluştururken `body.workspace` ile set edilir. `PATCH /api/campaign/:name` ile değiştirilebilir.

**İlgili fonksiyonlar:** `api/campaign/index.js` (yazma), `admin-renderer.js` client-side `isCampaignInWorkspace(c)` filtresi — `ws-select` dropdown değerine göre listeyi filtreler.

**Race condition / gecikme:** Yok. Workspace tamamen UI filtreleme mantığı — routing'e, AE olaylarına veya KV key yapısına etkisi yok. Birden fazla kişi aynı anda workspace değiştirirse son write kazanır (last-writer-wins, KV garanti eder).

---

### 2. Telemetry Ingestion Pipeline

**Nerede saklanır:** `LINKHUB_OPS` Analytics Engine dataset'i — ops olayları (`route_resolved`, `alias_click`, `route_fail_*`). `LINKHUB_EVENTS` — genel clickstream.

**Ne tetikler:** Alias route'una gelen her HTTP isteği (`/launch`, `/launch/offer`, vb.) → `[[path]].js` → `alias-router.js` `resolveAlias()` → `emitOps(env, OPS_EVENTS.ALIAS_CLICK, {...})` çağrısı.

**İlgili fonksiyonlar:** `[[path]].js` → `alias-router.js` → `ops-telemetry.js` `emitOps()`. `emitOps` Cloudflare AE'nin `.writeDataPoint()` metodunu çağırır, bu işlem `context.waitUntil()` ile fire-and-forget olarak yapılır.

**Race condition / gecikme:** `emitOps` `waitUntil` içinde çalışır — response döndürüldükten sonra tamamlanır. **Kritik gecikme:** AE ingestion pipeline'ı 30–60 saniye. Event yazıldı ama SQL sorgulanabilir hale gelmesi için bu pencere beklenmeli.

---

### 3. Analytics Ingestion Path

**Nerede saklanır:** `LINKHUB_OPS` AE dataset (`alias_click` index1). Admin Analytics tab verileri `CF_ACCOUNT_ID` + `CF_AE_API_TOKEN` kullanarak Cloudflare AE SQL API'si üzerinden okunur.

**Ne tetikler:** Alias click olayı → `emitOps(ALIAS_CLICK)`. Analytics tab açılışında `GET /api/admin/analytics` → AE SQL sorgusu.

**İlgili fonksiyonlar:** `api/admin/analytics.js`, `alias-router.js` `emitOps`, `background-test.js` `queryEventsSince()`.

**Race condition / gecikme:** AE SQL sorgusu sadece ingested (committed) olayları görür. 30–60s lag nedeniyle:
- Click hemen gerçekleşir → event yazılır → 30–60s geçer → SQL'de görünür
- Background test 95s retry window kullanır ama bu yeterli olmayabilir

---

### 4. Alias Compilation Triggers

**Nerede saklanır:** 
- **Truth source:** `ALIAS_REGISTRY["alias:{alias}"] = campaign_name`
- **Compiled output:** `ROUTE_TABLE["route:{alias}"] = canonical_slug`
- **Cache:** Workers in-memory `routeCacheSet()` (Workers Cache API)

**Ne tetikler (otomatik):**
| Olay | Handler | Koşul |
|---|---|---|
| Yeni campaign + alias | `POST /api/campaign` | `rawAlias !== null` |
| Yeni slug + alias | `POST /api/slug` | `rawAlias !== null` |
| Campaign alias değişimi | `PATCH /api/campaign/:name` | `rawAlias !== undefined` |
| Slug alias değişimi | `PUT /api/slug/:slug` | `rawAlias !== undefined` |

**Ne tetikler (manuel):** `POST /api/admin/compile-routes`

**Flow:** `compileRoutes(env)` → `buildCampaignSlugMap(LINKHUB_SLUGS)` → Phase A (campaign aliases) → Phase B (slug aliases) → `ROUTE_TABLE.put(route:X, slug)` × N → `invalidateRoutes([...keys])` (Workers Cache purge)

**Race condition:** `compileRoutes` `context.waitUntil()` içinde çalışır — response'dan **sonra** başlar. KV write (`ALIAS_REGISTRY.put`) await edilir, sonra `waitUntil` ateşlenir — dolayısıyla compile çalıştığında ALIAS_REGISTRY günceldir. **Ancak:** Campaign alias oluşturulduğunda henüz slug yoksa `buildCampaignSlugMap` bu campaign için boş döner → route yazılmaz. Çözüm: ilk slug oluşturulduğunda compile tekrar tetiklenir.

---

### 5. defaultSlug Persistence

**Nerede saklanır:** `LINKHUB_CAMPAIGNS[campaign_name].defaultSlug` alanı. KV'ye `PATCH /api/campaign/:name` ile yazılır.

**Ne tetikler (mevcut — 21.md sonrası):** Campaigns tab'daki `camp-default-slug-select` `change` olayı → anında `PATCH /api/campaign/:name` → KV write. **Compile trigger yok** — sadece KV'ye yazılır; bir sonraki `compileRoutes()` çalışmasında Phase A bu değeri okur.

**İlgili fonksiyonlar:** `admin-renderer.js` `renderCampaignList()` inline select → change handler, `api/campaign/[name].js` PATCH, `route-compiler.js` Phase A `campaignRecord?.defaultSlug` kontrolü.

**Problem (22.md'nin tespit ettiği):**
1. Dropdown, `slugCache` üzerinden render edilir — eğer `slugCache` henüz yüklenmediyse (campaigns önce gelirse) dropdown boş kalır
2. Selector edit panelinin dışında — alias ile ortak Save/Cancel akışı yok
3. `defaultSlug` değişimi compile trigger'lamıyor → `/alias` hâlâ eski slug'a gidebilir ta ki bir sonraki compile'a kadar

---

### 6. Background Diagnostics Pipeline

**Nerede saklanır:** `LINKHUB_CONFIG["_bg_test_last"]` — son test sonucu (ok, stage, reason, timestamp, fixture).

**Ne tetikler:** `POST /api/admin/background-test` (manual) veya harici Cron Trigger Worker.

**Adım adım flow:**
```
stage: telemetry  → CF_ACCOUNT_ID + CF_AE_API_TOKEN varlık kontrolü
stage: registry   → createFixture(env) → KV writes (ROUTE_TABLE ×3, LINKHUB_SLUGS, LINKHUB_CAMPAIGNS)
stage: router     → fireClickSequence(baseUrl, alias) → 4 HTTP req, 150ms arayla
stage: analytics  → retryWithBackoff(queryEventsSince) → [1s,2s,4s,8s,16s,32s,32s] = 95s max
stage: complete   → archiveFixture(env) → KV deletes
                 → storeResult → LINKHUB_CONFIG["_bg_test_last"]
```

**Race condition / gecikme:**
- **AE gecikme:** 30–60s ingestion, 95s retry penceresi. Eğer AE >95s gecikirse test false-negative döner — fixture doğru çalışmış olsa bile
- **Fixture orphan riski:** Archive, test sonucundan önce çalışır. Eğer `archiveFixture` başarısız olursa LINKHUB_SLUGS'ta test slug kalabilir (admin'de görünür)
- **Concurrent test riski:** İki eş zamanlı test farklı alias kullanır ama AE sorgusunda zaman tabanlı overlap olabilir — ancak `alias` ve `campaign` filter'ları bunu önler
- **Self-test HTTP loop:** `fireClickSequence` kendi Workers instance'ına istek atar — local dev'de `localhost:8789` kullanılır, prod'da `CF_PAGES_URL`

## B.4 — Duplicate Telemetry Investigation (DIAGNOSED — NO BUG FOUND)

**Root cause of "AE table: +2 vs Analytics UI: +1":**

`alias-router.js` emits **two** AE events per routed request:
1. `ROUTE_RESOLVED` — operational routing event (ops-only)
2. `ALIAS_CLICK` — marketing analytics event

Both go to `LINKHUB_OPS`. The analytics endpoint queries only `index1 = 'alias_click'`, so it counts 1 per click. The "AE table +2" is the raw `LINKHUB_OPS` row count which includes both event types. This is **correct behavior** — no code change needed.

## B.5 — Dynamic Admin Panel Version (DONE)

`functions/nilufer.js`:
- `onRequestGet()` now receives `{ env }` and passes `CF_PAGES_BRANCH` + `CF_PAGES_COMMIT_SHA` to `renderAdmin()`.

`functions/_shared/admin-renderer.js`:
- `renderAdmin()` signature changed to `renderAdmin({ branch = "", sha = "" } = {})`.
- Version tag derived from branch: `feat/v9-diagnostics` → `v9`.
- SHA appended: first 7 chars of `CF_PAGES_COMMIT_SHA`.
- New format: `Studio Panel v9 · abc1234` (or `Studio Panel v9` when sha absent).
- Used in both `<title>` and `.topbar-title`.

## B.6 — Stopwatch Moved to Toolbar (DONE)

`admin-renderer.js`:
- Removed Diagnostics tab Stopwatch card entirely.
- Added `<div class="sw-toolbar">` to topbar (between title and workspace selector).
- Icon-only buttons: `▶` (toggle start/stop → shows `⏸` when running), `⟳` (reset).
- Reset behavior: if running → reset + continue; if paused → reset + stay paused.
- CSS: `.sw-toolbar`, `.sw-time` added; topbar uses `gap` instead of `justify-content: space-between`.

## B.7 — Workspace Architecture Analysis (DOCS ONLY)

**Current behavior:**
- `workspace` is a string field on campaign records in `LINKHUB_CAMPAIGNS`.
- It is a **client-side UI filter only** — affects campaign list, slug list, campaign dropdown, and analytics tables in the admin panel.
- It has zero effect on routing, AE events, KV key structure, or public hub rendering.

**Answers to 22.md questions:**

1. **Does workspace safely isolate test data from production?**
   → No. Workspace filter is visual-only. Test campaigns are isolated by the `isTest: true` flag and `test-` name prefix, not by workspace. Both test and prod data coexist in the same KV namespaces and AE datasets.

2. **Would separate KV namespaces per workspace improve reliability?**
   → Technically yes — it would give true data isolation. However, given the small-scale, single-deployment nature of Campaign OS, this adds significant operational complexity (double KV bindings, separate route tables, separate compilers) for minimal gain. The `isTest: true` + prefix approach is sufficient for the current use case.

3. **Would such separation introduce unnecessary complexity?**
   → Yes. Not recommended at this stage. The current approach is correct for a single-tenant single-artist deployment.

**Conclusion:** No workspace refactor needed.
