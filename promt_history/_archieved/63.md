

# Prompt 63 — UTM Orchestration Layer

Context

The Campaign OS resolver is stable after P61 and P62.

Current pipeline:

alias → campaign → link metadata → destination → redirect

KV schema currently supports two formats:

1) Legacy string

https://example.com

2) Metadata JSON

{
  "destination": "https://example.com",
  "utm": {
    "source": "instagram",
    "medium": "bio",
    "campaign": "spring-2026"
  },
  "experiment": null
}

Resolver currently extracts `destination` but ignores `utm`.

We now introduce **UTM orchestration**.

The resolver should append UTM parameters when metadata contains a `utm` object.

---

Objective

When metadata contains:

utm: {
  source,
  medium,
  campaign
}

Resolver should produce final redirect URL:

<destination>?utm_source=...&utm_medium=...&utm_campaign=...

If destination already contains query parameters, UTM parameters must be appended using `&` instead of `?`.

Legacy string links must remain fully functional.

---

Implementation

Modify:

functions/campaign/[[path]].js

After metadata parsing in Step 4.

Current code produces:

const destination = ...

Extend logic:

let finalUrl = destination

if (parsed && typeof parsed === "object" && parsed.utm) {
  const utm = parsed.utm

  const params = new URLSearchParams()

  if (utm.source) params.append("utm_source", utm.source)
  if (utm.medium) params.append("utm_medium", utm.medium)
  if (utm.campaign) params.append("utm_campaign", utm.campaign)

  const query = params.toString()

  if (query) {
    finalUrl += destination.includes("?")
      ? `&${query}`
      : `?${query}`
  }
}

Redirect:

return Response.redirect(finalUrl, 302)

---

Behavior examples

KV:

{
  "destination": "https://site.com/page",
  "utm": {
    "source": "instagram",
    "medium": "bio",
    "campaign": "spring-2026"
  }
}

Request:

/campaign/spring-2026/ig

Redirect:

https://site.com/page?utm_source=instagram&utm_medium=bio&utm_campaign=spring-2026

---

If destination already contains query

Destination:

https://site.com/page?ref=homepage

Redirect:

https://site.com/page?ref=homepage&utm_source=instagram&utm_medium=bio&utm_campaign=spring-2026

---

Legacy behavior

If KV value is plain string:

"https://example.com"

Redirect remains unchanged.

---

Constraints

Do NOT:

• change KV keys
• change alias schema
• modify redirect status
• introduce analytics storage

This layer only constructs the final redirect URL.

---

Verification

Test with metadata KV value.

Expected redirect contains UTM parameters.

Example test URL:

https://links.niluferormanli.studio/campaign/test/test

Should redirect to:

https://example.com?utm_source=instagram&utm_medium=bio&utm_campaign=spring-2026

---

Goal

Introduce deterministic marketing attribution while keeping Campaign OS lightweight and edge-native.

This prepares the system for experiment routing and telemetry in the next steps.

## Implementation Summary (Prompt 63)

### Modified file: `functions/campaign/[[path]].js`

**Single addition — UTM orchestration (Step 5) between destination resolution and redirect.**

`parsed` hoisted to outer scope so Step 5 can access it:

```js
let destination;
let parsed = null;   // ← hoisted out of try/catch

try {
  parsed = JSON.parse(linkRaw);
  if (parsed?.destination) { destination = parsed.destination; }
  else { destination = linkRaw; parsed = null; }
} catch {
  destination = linkRaw; parsed = null;
}

// Step 5 — UTM orchestration
let finalUrl = destination;

if (parsed && typeof parsed === "object" && parsed.utm) {
  const utm = parsed.utm;
  const utmParams = new URLSearchParams();
  if (utm.source)   utmParams.append("utm_source",   utm.source);
  if (utm.medium)   utmParams.append("utm_medium",   utm.medium);
  if (utm.campaign) utmParams.append("utm_campaign", utm.campaign);
  const query = utmParams.toString();
  if (query) finalUrl += destination.includes("?") ? `&${query}` : `?${query}`;
}
```

**Behavior matrix:**
| KV value | Result |
|---|---|
| `"https://example.com"` (legacy string) | `302 https://example.com` — unchanged |
| `{"destination":"https://example.com"}` (no utm) | `302 https://example.com` — unchanged |
| `{"destination":"https://example.com","utm":{"source":"instagram","medium":"bio","campaign":"spring-2026"}}` | `302 https://example.com?utm_source=instagram&utm_medium=bio&utm_campaign=spring-2026` |
| destination already has `?` | UTMs appended with `&` |

Legacy string links: `parsed = null` → Step 5 is a no-op → `finalUrl === destination`.
