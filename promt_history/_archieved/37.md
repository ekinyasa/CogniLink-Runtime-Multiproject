# Prompt 37 — Experiment Lifecycle Engine

## Objective
Add a lightweight **experiment lifecycle layer** to Campaign OS so experiments can move through clear operational states after a winner is detected.

The goal is to allow the system to:

• pause experiments
• promote winners
• archive finished experiments

while keeping the engine **deterministic, minimal, and KV‑friendly**.

Design principle:

```
experiments are temporary
campaigns are permanent
```

The lifecycle layer must not complicate the routing engine.

---

# Experiment States

Each experiment must exist in one of four states:

```
RUNNING
PAUSED
DECIDED
ARCHIVED
```

Definitions:

RUNNING
→ traffic split between variants

PAUSED
→ routing continues but exposure counters freeze

DECIDED
→ winner detected but routing still split

ARCHIVED
→ experiment closed, routing bypasses A/B logic

The routing engine must interpret lifecycle state.

RUNNING

```

```

```

```

# Summary — Prompt 37 Implementation

## Architecture

The lifecycle layer is a thin state-machine overlay on top of the existing KV AB config. No new KV namespaces. No schema migrations. All lifecycle fields are **optional** — existing records without them default to `RUNNING`.

### State machine

```
RUNNING  ──pause──▶ PAUSED  ──resume──▶ RUNNING
RUNNING  ──archive─▶ ARCHIVED
PAUSED   ──archive─▶ ARCHIVED
DECIDED  ──pause──▶ PAUSED
DECIDED  ──archive─▶ ARCHIVED (with or without winner)
DECIDED  ──promote─▶ ARCHIVED (winner required; sets routing to winner slug)
ARCHIVED ──*──▶ 400 invalid_transition  (terminal)
```

---

## Files created

### `functions/api/experiment/_lifecycle.js` (shared helper)
`applyLifecycleTransition(request, env, targetState, allowedFrom)` — reads the current `ab_config:<alias>` from `ALIAS_REGISTRY`, validates the transition, writes the updated record back, and returns a JSON response. Used by pause/resume/archive. Idempotent: same-state transitions return `{ ok: true, noop: true }` without a KV write.

### `functions/api/experiment/pause.js`
`POST /api/experiment/pause` — transitions RUNNING or DECIDED → PAUSED. Uses shared helper.

### `functions/api/experiment/resume.js`
`POST /api/experiment/resume` — transitions PAUSED → RUNNING. Uses shared helper.

### `functions/api/experiment/archive.js`
`POST /api/experiment/archive` — transitions RUNNING / PAUSED / DECIDED → ARCHIVED. No winner promotion. Uses shared helper.

### `functions/api/experiment/promote.js`
`POST /api/experiment/promote` — DECIDED → ARCHIVED + sets `winner` on the record. Requires `abConfig.winner !== null` (stored winner). Winner slug becomes the deterministic route in ARCHIVED state. Separate handler (not via shared helper) because of the winner validation requirement.

All four endpoints: Bearer token auth · direct KV read (bypasses in-memory cache) · `Cache-Control: no-store`.

## Design decisions

- **PAUSED ≠ no routing** — routing continues so returning visitors see a consistent variant; only the counter writes are skipped. This preserves experiment integrity across a pause.
- **ARCHIVED routing** — always serves `abConfig.winner` if set (Promote path), or falls back to `canonicalSlug` (Archive-without-winner path). This guarantees deterministic post-experiment traffic.
- **Promote requires stored winner** — `stored_winner` (from the KV record) must be non-null. The dashboard's Promote button only appears when the API returns `stored_winner !== null`. This prevents accidental promotion when analytics haven't yet detected a winner.
- **In-memory cache lag** — lifecycle writes go directly to KV but the in-memory `ab-router.js` cache has a 60 s TTL. Routing state changes propagate within one cache interval (~60 s). This is acceptable for admin operations.
- **Confirm dialogs** — Promote and Archive require `window.confirm()` before firing to prevent accidental destructive state changes.
