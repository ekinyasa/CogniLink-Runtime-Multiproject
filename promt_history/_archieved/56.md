We are extending the Campaign OS edge router with a lightweight experiment telemetry layer.

Current system architecture:

- Cloudflare Worker router
- Stateless routing
- Campaign KV registry
- Random assignment + cookie stickiness
- LinkHub pages rendered by the worker

We now want to add a minimal telemetry foundation to measure experiment performance.

Important constraints:

1. The router must remain extremely fast.
2. Telemetry must never block routing.
3. All telemetry should be fire-and-forget.
4. No heavy dependencies.
5. Must run entirely in the Cloudflare Worker environment.

Goal of this prompt:
Implement a minimal telemetry system to capture experiment exposure and user interactions.

--------------------------------

STEP 1 — Telemetry endpoint

Create a worker endpoint:

/t

Example request:

/t?e=exposure&exp=ab-rand-45&v=igbio

Parameters:

e = event type
exp = experiment id
v = variant

Supported events:

exposure
click
conversion

--------------------------------

STEP 2 — Storage model

For now implement simple KV counters:

telemetry:exp:<experiment>:<variant>:exposure
telemetry:exp:<experiment>:<variant>:click
telemetry:exp:<experiment>:<variant>:conversion

Each event increments the appropriate counter.

Example:

telemetry:exp:ab-rand-45:igbio:exposure

Use atomic increment logic.

--------------------------------

STEP 3 — Router exposure logging

When the router assigns a variant:

fire a telemetry request:

/t?e=exposure&exp=<experiment>&v=<variant>

Important:

Do NOT await this request.

Use:

fetch(url, { method: "GET", keepalive: true })

Routing must never block.

--------------------------------

STEP 4 — Client click telemetry

Inside the generated LinkHub page:

attach a click handler to outbound links.

When a user clicks a link:

send

/t?e=click&exp=<experiment>&v=<variant>

Use navigator.sendBeacon when possible.

Fallback to fetch with keepalive.

--------------------------------

STEP 5 — Safety rules

Telemetry must:

- never throw errors
- never block routing
- fail silently

## Implementation Summary

### Files Created

#### `functions/t.js` — telemetry endpoint (`GET /t`)

**Query parameters:** `e` (event type), `exp` (experiment ID), `v` (variant slug)

**Behaviour:**
1. Returns HTTP 200 immediately — response never waits for KV
2. Sanitizes params with regex `^[a-zA-Z0-9_:.-]+$` (max 200 chars)
3. Silently drops invalid/missing params
4. Schedules KV read-modify-write via `context.waitUntil()` to increment `telemetry:exp:<exp>:<v>:<e>` in `ALIAS_REGISTRY`
5. Never throws; all errors caught silently

**KV key examples:**
```
telemetry:exp:ab-rand-45:igbio:exposure
telemetry:exp:ab-rand-45:igbio:click
telemetry:exp:ab-rand-45:igbio:conversion
```

These keys are separate from the bandit learning counters (`exp:<alias>:<slug>:<type>:<shard>`). The telemetry keys are simple (non-sharded) counters for human inspection; the `exp:*` sharded keys remain the authoritative source for the bandit.

### Files Modified

#### `functions/lib/experiment-router.js`

Fire-and-forget exposure ping added in the `RUNNING/PAUSED` branch, after variant selection, before `emitOps`:

```js
if (expState === "RUNNING") {
  try {
    const origin       = new URL(request.url).origin;
    const telemetryUrl = `${origin}/t?e=exposure`
      + `&exp=${encodeURIComponent(alias)}`
      + `&v=${encodeURIComponent(finalSlug)}`;
    fetch(telemetryUrl, { method: "GET", keepalive: true }).catch(() => {});
  } catch (_) { /* fail silently */ }
}
```

- Only fires for `RUNNING` (matches the existing `incrementExpCounter` gate — PAUSED experiments freeze data collection)
- Not awaited; `keepalive: true` lets the request survive the response lifecycle
- Wrapped in `try/catch` — telemetry never affects routing

#### `functions/_shared/hub-renderer.js`

`fireTelemetryClick()` function added inside the IIFE, between `fireOutbound` and the link wiring section:

```js
function fireTelemetryClick() {
  var exp = ROUTE_DEFAULTS.utm_experiment;
  var v   = ROUTE_DEFAULTS.utm_variant;
  if (!exp || !v) return;
  var url = "/t?e=click"
    + "&exp=" + encodeURIComponent(exp)
    + "&v="   + encodeURIComponent(v);
  try {
    if (typeof navigator !== "undefined" && navigator.sendBeacon) {
      navigator.sendBeacon(url);
    } else {
      fetch(url, { method: "GET", keepalive: true }).catch(function () {});
    }
  } catch (e) {}
}
```

Called from the link click handler alongside the existing `fireOutbound`:
```js
el.addEventListener("click", function () {
  var resolved = buildHref(meta.href, meta.utmContent, meta.noUtm);
  el.href = resolved;
  fireOutbound(meta.id, resolved);
  fireTelemetryClick();            // ← added
});
```

Uses `navigator.sendBeacon` (survives page navigation) with `fetch + keepalive` fallback. Only fires when `ROUTE_DEFAULTS.utm_experiment` and `utm_variant` are both present.

### End-to-end telemetry flow

```
User visits hub page
  → experiment-router.js fires fetch /t?e=exposure (fire-and-forget)
  → functions/t.js increments telemetry:exp:<alias>:<slug>:exposure

User clicks a link
  → hub-renderer.js fires navigator.sendBeacon /t?e=click
  → functions/t.js increments telemetry:exp:<alias>:<slug>:click
```

### Safety properties

| Rule | How enforced |
|---|---|
| Never block routing | `fetch()` not awaited; `keepalive: true` |
| Never block navigation | `navigator.sendBeacon` (detached from page lifecycle) |
| Never throw | All paths wrapped in `try/catch` + `.catch(() => {})` |
| Always 200 | `/t` returns 200 regardless of KV state |
| No heavy dependencies | Pure Workers API + KV only |
