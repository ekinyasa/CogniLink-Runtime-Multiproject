# Prompt 62 — Link Metadata Layer (Backward Compatible)

Context

The Campaign OS resolver is working and production-safe after Prompt 61.

Current KV schema:

alias:<alias> -> campaign
link:<campaign>:<linkId> -> destination URL (string)

Example:

alias:test -> demo
link:demo:test -> https://example.com

We now introduce a metadata layer while remaining fully backward compatible.

---

Objective

Allow link KV values to optionally be JSON objects instead of plain strings.

Both formats must continue working.

Old format (still valid):

https://example.com

New format:

{
  "destination": "https://example.com",
  "utm": {
    "source": "instagram",
    "medium": "bio",
    "campaign": "spring-2026"
  },
  "experiment": null
}

Resolver must always extract the final redirect URL from this structure.

---

Implementation

Modify:

functions/campaign/[[path]].js

After link lookup:

// Resolver must remain fully backward compatible with existing string-based KV entries,
// while allowing for future expansion to metadata objects.

const raw = await env.LINKHUB_SLUGS.get(`link:${campaign}:${linkId}`)

if (!raw) {
  return new Response("link not found", { status: 404 })
}

let destination

// Backward compatible parsing
// KV value may be:
// 1) plain string URL
// 2) JSON metadata object

try {
  const parsed = JSON.parse(raw)

  if (
    parsed &&
    typeof parsed === "object" &&
    typeof parsed.destination === "string"
  ) {
    destination = parsed.destination
  } else {
    // JSON parsed but not a valid metadata object
    destination = raw
  }

} catch {
  // Value is a plain string URL
  destination = raw
}

Redirect remains identical:

return Response.redirect(destination, 302)

---

Constraints

Do NOT change:

• alias schema
• KV keys
• routing grammar
• redirect logic

This change only introduces metadata capability.

---

Verification

Both must work:

/campaign/test/test
→ https://example.com

KV value = string

AND

KV value = JSON:

{
  "destination": "https://example.com"
}

---

Goal

Prepare Campaign OS for:

• UTM orchestration
• experiment routing
• analytics metadata

without breaking existing links.

## Implementation Summary (Prompt 62)

### Modified file: `functions/campaign/[[path]].js`

**Single change — backward-compatible destination resolution after link lookup.**

Step 3 (link lookup) now reads into `linkRaw` instead of `destination`. New Step 4 parses `linkRaw`:

```js
let destination;
try {
  const parsed = JSON.parse(linkRaw);
  if (parsed && typeof parsed === "object" && typeof parsed.destination === "string") {
    destination = parsed.destination;       // JSON metadata object
  } else {
    destination = linkRaw;                  // valid JSON but unknown shape → treat as URL
  }
} catch {
  destination = linkRaw;                    // plain string URL (legacy)
}
```

**Decision table:**
| KV value | `JSON.parse` result | `destination` |
|---|---|---|
| `"https://example.com"` | throws | `"https://example.com"` |
| `{"destination":"https://example.com","utm":{...}}` | object with `.destination` string | `"https://example.com"` |
| `{"foo":"bar"}` | object without `.destination` | raw string (pass-through) |

All other logic (path parsing, alias lookup, link lookup, telemetry, redirect) unchanged.

**Future fields available in JSON format:**
```json
{
  "destination": "https://example.com",
  "utm": { "source": "instagram", "medium": "bio", "campaign": "spring-2026" },
  "experiment": null
}
```
UTM orchestration and experiment routing will read these in later prompts.
