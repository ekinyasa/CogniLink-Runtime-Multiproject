# Prompt 38 — Auto Winner Detection + Winner Persistence

## Objective
Extend the experiment analytics engine so that **winners detected by analytics are automatically persisted into the experiment lifecycle state**.

This removes the manual step between:

```
analytics winner detection
→ lifecycle stored_winner
→ Promote Winner availability
```

and prepares Campaign OS for **automatic experiment optimization**.

---

# Design Principle

Analytics decides who is winning.
Lifecycle decides what to do with it.

The bridge between them is **winner persistence**.

```
analytics winner
→ stored_winner
→ lifecycle UI
→ optional promotion
```

---

# KV Schema Update

Extend the lifecycle metadata to persist the detected winner.

Example record:

```json
{
  "experiment": "abtest",
  "state": "DECIDED",
  "winner": "cd26-test-yt",
  "created_at": 1710000000,
  "decided_at": 1710001200,
  "archived_at": null
}
```

Meaning:

```
winner = canonical variant slug
```

This field becomes the **source of truth for routing when promoted**.

---

# Analytics → Lifecycle Bridge

When `/api/experiments` aggregates variant metrics it must evaluate a winner.

Winner rule (simple deterministic heuristic):

```
minimum exposures per variant ≥ 30
AND
conversion_rate difference ≥ 10%
```

If rule satisfied:

```
state = DECIDED
winner = variant slug
store decided_at timestamp
```

Important:

This operation must be **idempotent**.

Meaning:

```
if stored_winner already exists
→ do nothing
```

---

# Router Behaviour Update

Router must prioritize lifecycle winner when state is DECIDED or ARCHIVED.

Rules:

```
RUNNING
→ normal split

PAUSED
→ sticky variant but counters frozen

DECIDED
→ split continues but stored_winner available

ARCHIVED
→ always route to stored_winner
```

---

# Promote Winner Logic Update

Promote button behaviour becomes:

```
state = ARCHIVED
routing always serves stored_winner
exposure counters disabled
```

If stored_winner missing:

```
return 400 "winner_not_available"
```

# Summary — Prompt 38 Implementation

## Architecture

The analytics → lifecycle bridge is a fire-and-forget KV write triggered inside `GET /api/experiments`. No new KV namespaces. No cron jobs. The bridge is activated lazily on every analytics read, guarded by an idempotency check so it only writes once.

### Auto-persist flow

```
GET /api/experiments?alias=X
  → aggregate counters
  → evaluate winner heuristic (≥ 30 exposures, ≥ 10 pp conv. rate gap)
  → if winner AND no stored_winner AND state is RUNNING/DECIDED
      → context.waitUntil(persistDetectedWinner(...))   // fire-and-forget
      → effectiveStoredWinner = winnerSlug              // optimistic response
      → effectiveState = "DECIDED"                      // optimistic response
  → return analytics payload
```

## Files modified

### `functions/api/experiments.js`
- `WINNER_THRESHOLD`: `0.05` → `0.10` (10 pp absolute gap required)
- Added `persistDetectedWinner(env, alias, winnerSlug)` — async, fire-and-forget; does direct KV read before writing (idempotent: exits if `current.winner` already set); writes `state: "DECIDED"`, `winner: slug`, `decided_at: unix_ts`
- Auto-persist logic in `onRequestGet`: fires `context.waitUntil()` when winner detected and no stored winner exists, and state is RUNNING or DECIDED
- `effectiveStoredWinner` — optimistic: set to `winnerSlug` on the same call that triggers the KV write so the UI shows the winner immediately without waiting for cache expiry
- `effectiveState` — returns `"DECIDED"` immediately when `effectiveStoredWinner` is set and KV state is still RUNNING
- Response now returns `effectiveState` and `effectiveStoredWinner`

### `functions/admin/experiments.js`
- `.sc-badge.b-archived` color: `#374151` → `#B91C1C` (red); dark mode `#7F1D1D` → `#991B1B`
- ARCHIVED badge label: `"ARCHIVED"` → `"EXPERIMENT CLOSED"`

- Winner stat row: `👑 <slug>` when `storedWinner` is set; `❓ <slug>` when analytics-only winner (not yet persisted)
- Added `btn-lc-unarchive` button + `.btn-lc-unarchive` CSS (outline-red style)
- `elBtnUnarchive` DOM ref; added to `allBtns` array; click handler with `confirm()` → `lifecycleAction('unarchive')`

  - `ARCHIVED` → Unarchive only

## Files created

### `functions/api/experiment/unarchive.js`
`POST /api/experiment/unarchive` — reopens a closed experiment.
- Allowed transition: `ARCHIVED → PAUSED`
- Uses `applyLifecycleTransition(request, env, "PAUSED", ["ARCHIVED"])`
- Counters remain unchanged; stored winner is preserved
- Bearer token auth; `Cache-Control: no-store`

---

## Design decisions

- **Optimistic response**: `effectiveStoredWinner` and `effectiveState` are set on the same API call that triggers the KV write. The UI reflects the winner immediately without requiring a second round-trip or waiting for the 60 s in-memory cache to expire.
- **Double-write safety**: `persistDetectedWinner` does a fresh direct KV read before writing. If two requests race during the cache window, the second writer sees `current.winner` already set and exits without writing. The result is always the same value.
- **10 pp threshold**: Raised from 5 pp to reduce false positives on small sample sizes where noise can cross the lower threshold.
- **Unarchive → PAUSED (not RUNNING)**: Reopened experiments resume with counters frozen, giving the admin a chance to review before re-enabling counter writes via Resume.
- **Promote guard**: The dashboard's Promote button is only shown when `storedWinner !== null` AND `lifecycleState === "DECIDED"`. `promote.js` enforces the same check server-side, preventing promotion without a confirmed winner.
