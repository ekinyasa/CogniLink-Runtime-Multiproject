

# Prompt 52 — Exposure Token System (Conversion Integrity)

You are working inside the Campaign OS Cloudflare Workers codebase that powers the Nilüfer Ormanlı campaign routing and experiment engine.

Previous step (Prompt 51) extracted the experiment router.  
Now we must secure the **conversion pipeline** so conversions can only originate from real experiment exposures.

Currently the endpoint:

POST /api/convert

can be triggered directly and therefore conversions can be artificially inflated.  
This breaks experiment validity and bandit learning.

Your task is to implement an **Exposure Token System**.

IMPORTANT: This is a **minimal integrity layer**, not a full authentication system.

---

# Goal

Guarantee that:

1. A conversion can only be recorded if the user was actually exposed to a variant.
2. The token cannot be forged or reused.
3. The system adds **almost zero latency** to the redirect pipeline.

---

# High Level Flow

Current flow:

request
→ experiment router
→ redirect to final slug
→ user later triggers /api/convert

New flow:

request
→ experiment router
→ generate exposure token
→ redirect to final slug WITH token
→ conversion endpoint validates token
→ record conversion

---

# Exposure Token Design

Token must contain:

- experiment alias
- variant slug
- timestamp
- nonce

Example payload:

{
  alias: "abrand45",
  variant: "ab-rand-45-igbio",
  ts: 1773507000,
  nonce: "random"
}

The payload must be **HMAC signed** using a secret stored in environment variables.

Use:

EXPOSURE_TOKEN_SECRET

Signature:

HMAC_SHA256(payload_json, secret)

Final token format:

base64(payload).base64(signature)

---

# Token Generation

Token must be generated inside the experiment router after a variant is selected.

Add token to redirect URL as:

?exp_token=TOKEN

If URL already has query parameters, append normally.

Example:

/landing-page?utm_campaign=spring&exp_token=...

---

# Token Validation

Inside:

POST /api/convert

Add validation step:

1. Parse exp_token
2. Verify HMAC signature
3. Validate timestamp (max age: 24h)
4. Ensure alias + variant match the conversion request
5. Reject if token invalid

If invalid:

return HTTP 400.

---

# Replay Protection

Add lightweight replay protection using KV.

When a token is used:

KV.put(
  "exp_used:" + token_hash,
  "1",
  { expirationTtl: 86400 }
)

If token already exists:

reject conversion.

---

# Performance Constraints

- Token generation must be synchronous and extremely fast.
- Token validation must not perform heavy crypto repeatedly.
- Use built-in Web Crypto API where possible.

## Implementation Summary

### Files Created

**`functions/lib/exposure-token.js`**

Two exported async functions:

`generateExposureToken(alias, variant, env)` → `string | null`
- Builds payload: `{ alias, variant, ts: unixSec, nonce: base64url(8 random bytes) }`
- Signs with `HMAC-SHA256(payloadJson, EXPOSURE_TOKEN_SECRET)` via Web Crypto
- Returns `base64url(payloadJson) + "." + base64url(signature)`
- Returns `null` when `EXPOSURE_TOKEN_SECRET` is not bound (graceful degradation)
- Module-level `CryptoKey` cache — `importKey()` called at most once per isolate lifetime

`verifyExposureToken(token, alias, variant, env)` → `{ ok: true, nonce } | { ok: false, reason }`
- Splits token at last `.`; decodes payload bytes + signature bytes
- Verifies HMAC using `crypto.subtle.verify()` (constant-time — no timing attack surface)
- Validates timestamp: rejects `ts > now + 300s` (future) or `now - ts > 86400s` (expired)
- Verifies `payload.alias === alias` and `payload.variant === variant`
- Returns `nonce` so the caller can perform replay protection

### Files Modified

**`functions/lib/experiment-router.js`**
- Added import: `generateExposureToken` from `./exposure-token.js`
- `resolveExperimentVariant` changed from synchronous to `async`
- Token generated after variant resolution for all `abActive=true` states (RUNNING, PAUSED, DECIDED, ARCHIVED)
- DRAFT returns `expToken: null` (no exposure, no token)
- New return field: `expToken: string | null`
- All existing routing behavior unchanged

**`functions/[[path]].js`**
- `resolveExperimentVariant` call now `await`ed
- After `defaultUtms` assembly, adds token to hub link params when present:
  ```js
  if (expResult?.expToken) defaultUtms.exp_token = expResult.expToken;
  ```
- Token reaches all hub links via the existing client-side `buildHref()` in `hub-renderer.js` — no renderer changes required

**`functions/api/convert.js`**
- Added import: `verifyExposureToken` from `../lib/exposure-token.js`
- Parses `exp_token` from request body alongside existing fields
- Validation block (active only when `EXPOSURE_TOKEN_SECRET` is bound):
  1. Token must be present → `token_required` (400)
  2. `verifyExposureToken()` must pass → `token_invalid` (400) with `reason` subfield
  3. Replay check: `ALIAS_REGISTRY.get("exp_used:<nonce>")` → `token_already_used` (400)
  4. Nonce consumed: `ALIAS_REGISTRY.put("exp_used:<nonce>", "1", { expirationTtl: 86400 })` via `context.waitUntil()`

### Token Flow

```
Hub page request:
  [[path]].js → resolveExperimentVariant() → generates HMAC token
  → defaultUtms.exp_token = token
  → renderHub() → client-side buildHref() appends ?exp_token=... to all links

User clicks link → lands on LP:
  /lp?utm_experiment=alias&utm_variant=slug&exp_token=<base64url>.<base64url>

LP fires conversion:
  POST /api/convert { experiment, variant, exp_token }
  → verifyExposureToken() — HMAC check + age + alias/variant binding
  → ALIAS_REGISTRY.get("exp_used:<nonce>") — replay check
  → incrementExpCounter() — conversion recorded
  → ALIAS_REGISTRY.put("exp_used:<nonce>") — nonce consumed (24h TTL)
```

### Graceful Degradation

When `EXPOSURE_TOKEN_SECRET` is **not** set:
- `generateExposureToken()` returns `null` — no `exp_token` added to hub links
- `convert.js` skips validation entirely — existing LP integrations keep working

When `EXPOSURE_TOKEN_SECRET` **is** set:
- All hub links include `exp_token` as a query parameter
- `convert.js` requires a valid, non-expired, non-replayed token
- LP integration snippet must be updated to read and forward `exp_token`

### Performance

- Generation: 1 × `crypto.subtle.sign()` (~0.1–0.5 ms), cached key — does not block hub render
- Validation: 1 × `crypto.subtle.verify()` + 1 × KV read — fast and parallel-compatible
- `importKey()` called once per isolate, cached in module scope for subsequent requests
- No new KV namespace required — replay nonces stored in `ALIAS_REGISTRY` with auto-expiry TTL

### Error Codes on Token Failure

| Error code | Status | Meaning |
|------------|--------|---------|
| `token_required` | 400 | Secret is set but `exp_token` field absent |
| `token_invalid` | 400 | Bad signature, expired, or field mismatch; see `reason` |
| `token_already_used` | 400 | Nonce already consumed — replay rejected |

`reason` subfield values: `token_expired`, `token_future_ts`, `token_invalid_signature`, `token_alias_mismatch`, `token_variant_mismatch`, `token_malformed`, `token_decode_failed`
