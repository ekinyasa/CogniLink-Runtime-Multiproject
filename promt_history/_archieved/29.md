# Implementation Summary

## File changed

`functions/_shared/admin-renderer.js` — `loadToken()` only. No other files touched.

## Root cause

Prompt 28 correctly changed `loadToken / saveToken / clearToken` to use
`TOKEN_KEY = "admin_token"`, and the login submit handler already used `saveToken(t)`.

However, browsers that had authenticated **before Prompt 28** still held the token under
`"_sp_tok"` (the key written by the pre-Prompt-28 panel). On those sessions:

```
loadToken()               → reads "admin_token" → not found → token = ""
gate form submit          → saveToken(t)        → writes "admin_token" ✓  (new sessions OK)
                          ↑ but old sessions never re-typed the token
```

`Object.keys(localStorage) → ["_sp_tok"]` confirmed: the browser had a live token
under the old key that was never migrated, so `loadToken()` found nothing and
`apiFetch()` sent `Authorization: Bearer ` (empty) → 401 on every request.

## Diff

```diff
  function loadToken() {
-   try { token = localStorage.getItem(TOKEN_KEY) || ""; } catch (e) {}
+   try {
+     // One-time migration: port token from legacy "_sp_tok" key (written by panel
+     // versions before Prompt 28). Runs once at boot; noop on every load thereafter.
+     var legacy = localStorage.getItem("_sp_tok");
+     if (legacy && !localStorage.getItem(TOKEN_KEY)) {
+       localStorage.setItem(TOKEN_KEY, legacy);
+       localStorage.removeItem("_sp_tok");
+     }
+     token = localStorage.getItem(TOKEN_KEY) || "";
+   } catch (e) {}
    return token;
  }
```

## How the migration works

1. Panel boots → `loadToken()` runs.
2. Checks whether `"_sp_tok"` exists **and** `"admin_token"` does not.
3. If yes: copies value to `"admin_token"`, removes `"_sp_tok"`.
4. Then reads `"admin_token"` as normal.
5. On the next boot (and all future boots): `"_sp_tok"` is gone → condition is false → noop.

## Post-fix auth flow

```
localStorage["_sp_tok"]  (old browser)
       ↓  loadToken() migration (Prompt 29)
localStorage["admin_token"]
       ↓  token in-memory variable
       ↓  authHeaders() on every apiFetch
  Authorization: Bearer <token>
       ↓  verifyToken() → ok
```

New browsers (no `"_sp_tok"`) are unaffected — they go straight to reading `"admin_token"`.

- `verifyToken()`, API routes, routing system, KV logic — untouched.
