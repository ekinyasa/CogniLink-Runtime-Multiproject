### Panel 2 — Conversion by Alias

**How data is recorded (`functions/t.js`):**

```
GET /t?e=conversion&exp=<exp>&v=<variant>&alias=<alias>
```

When `alias` param is present, a conversion event now also increments:

```
conv:alias:<experiment>:<alias>
```

KV counter incremented fire-and-forget via `context.waitUntil()`.

**How data is read (`functions/api/experiments.js`):**

New `loadBreakdowns(env, alias)` helper:
- `env.ALIAS_REGISTRY.list({ prefix: "conv:alias:<alias>:" })` — discovers known aliases
- Fetches counter values in parallel
- Returns `alias_conversions: [{ name, conversions }]` sorted desc

Fires in parallel with `getExpCounters()` via `Promise.all([...])`.

Included in `/api/experiments?alias=<alias>` response as `alias_conversions`.

**How it appears (`functions/admin/experiments.js`):**

Card: `conv-alias-card` (LAYER 3.6) — hidden until data exists.

Table columns: Alias | Conversions (with percentage of total).

### Panel 3 — Conversion by Hub Link

**How data is recorded (`functions/t.js`):**

```
GET /t?e=conversion&exp=<exp>&v=<variant>&link_id=<link_id>
```

When `link_id` param is present, a conversion event now also increments:

```
conv:link:<experiment>:<link_id>
```

**How data is read (`functions/api/experiments.js`):**

Same pattern as alias — `list({ prefix: "conv:link:<alias>:" })` discovers keys.

Included in response as `link_conversions: [{ name, conversions }]`.

**How it appears (`functions/admin/experiments.js`):**

Card: `conv-link-card` (LAYER 3.7) — hidden until data exists.

Table columns: Link | Conversions (with percentage of total).
