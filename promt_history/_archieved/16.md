

Campaign OS – Prompt 16.md

Context

Prompt 15.md introduced a unified system tester with:

• smoke test
• consistency probe
• manual validation
• hub link integrity

Real‑world testing shows the following behavior:

Router, modifier routing, KV registry, telemetry, analytics ingestion and hub integrity all PASS consistently.

However **manual validation still FAILS**, even though the analytics panel clearly shows the expected events appearing later.

Observed data from production testing:

• Analytics Engine ingestion latency ≈ 52–57 seconds
• System test duration ≈ 64 seconds
• Manual validation uses retry window ≈ 63 seconds

Because manual validation events are generated **after smoke test events and other system activity**, the effective ingestion delay may exceed the current retry window.

Result: manual validation falsely fails even though the system is working correctly.

Goal of Prompt 16

Stabilize manual validation so that it correctly detects the generated events even with longer AE ingestion latency.

Important rule:

Do NOT modify router behavior or analytics schema.
Only adjust testing logic.

--------------------------------------------------

PART 1 — Increase Retry Window

Update retryWithBackoff delays to:

[1000, 2000, 4000, 8000, 16000, 32000, 32000]

Maximum window ≈ 95 seconds.

This ensures the tester can tolerate:

• long Analytics Engine ingestion
• parallel smoke test traffic
• edge buffering delays

--------------------------------------------------

PART 2 — Fix Manual Validation Detection Logic

Manual validation currently requires strict event counts.

Because smoke tests and other requests run concurrently, strict counts can produce false failures.

Replace strict counting with **minimum event detection**.

Manual validation should PASS when the following conditions are met:

• At least 4 events for alias "nb" after test_start
• At least one event with modifier "offer"
• At least one event with modifier "vsl"

Do NOT require exact counts.

--------------------------------------------------

PART 3 — Improve Event Query Window

Analytics query must use a slightly earlier timestamp window to avoid race conditions.

Instead of:

WHERE timestamp >= test_start

Use:

WHERE timestamp >= (test_start - 5 seconds)

This protects against small clock drift between worker execution and analytics ingestion.

--------------------------------------------------

PART 4 — Ignore Pre‑Existing Events

Manual validation must filter events using:

alias = "nb"

AND

campaign = "new-beta"

AND

timestamp >= (test_start - 5 seconds)

This prevents older campaign traffic from affecting the test.

--------------------------------------------------

PART 5 — Improve Diagnostic Warning

If manual validation still fails after the retry window, return a clearer warning message:

"Manual validation timeout. Events may appear after the retry window due to Analytics Engine ingestion delay."

Do NOT mark the entire system test as failed if:

• router
• modifier
• telemetry
• analytics ingest

all passed.

Instead:

Return overall status:

ok: true

but include manual_validation: "delayed".

Example result:

{
  ok: true,
  results: {
    router: "pass",
    modifier: "pass",
    kv: "pass",
    telemetry: "pass",
    analytics: "pass",
    consistency: "pass",
    manual_validation: "delayed",
    hub_integrity: "pass"
  },
  duration_ms: number,
  warnings: [
    "Manual validation delayed due to AE ingestion latency"
  ]
}

--------------------------------------------------

Expected Outcome

After implementing Prompt 16:

• System Test should reliably PASS
• Manual validation should no longer produce false failures
• Long Analytics Engine ingestion delays will be tolerated
• Diagnostics UI will remain accurate and stable

Campaign OS will then have a fully reliable automated tester.

### PART 1 ✅ — Retry Window Genişletildi (`retry.js`)

```js
// Eski (~63s):
const DEFAULT_DELAYS = [1000, 2000, 4000, 8000, 16000, 32000];
```

Ek 32s adım paralel smoke test trafiğini ve edge buffering gecikmesini karşılar.

### PART 2 ✅ — Minimum Event Detection (15.md'de zaten doğru)

`runManualTest()` 15.md'den itibaren `>=` threshold kullanıyor:
```js
const ok = total >= EXPECTED.alias && offer >= EXPECTED.offer && vsl >= EXPECTED.vsl;
```
Kesin sayı gerektirmiyor — değişiklik gerekmedi. ✓

### PART 3 ✅ — -5s Clock Buffer (`manual-test.js`)

```js
// Eski:
const since = fmtTs(testStartMs);

// Yeni:
const since = fmtTs(testStartMs - 5_000);  // 5s buffer for clock drift
```

Worker clock (Date.now()) ile AE ingestion timestamp'i arasındaki küçük kaymaları önler.

### PART 4 ✅ — Campaign Filtresi (`manual-test.js`)

Her iki AE sorgusuna `AND blob4 = 'new-beta'` eklendi:

```sql
WHERE index1 = 'alias_click'
  AND blob1 = 'nb'
  AND blob4 = 'new-beta'      -- ← YENİ: eski campaign trafiğini dışlar
  AND timestamp >= '2026-03-07 10:00:00'
```

`TEST_CAMPAIGN = "new-beta"` sabiti eklendi.

### PART 5 ✅ — "delayed" Status + Diagnostics UI

**`system-test.js` — Yeni mantık:**
```js
const coreInfraPassed =
  infraResults.router    === "pass" &&
  infraResults.modifier  === "pass" &&
  infraResults.telemetry === "pass" &&
  infraResults.analytics === "pass";

const manualStatus = manual.ok       ? "pass"
  : coreInfraPassed                  ? "delayed"  // ← YENİ
  : "fail";

// ok = true hem "pass" hem "delayed" için

  key === "manual_validation" ? val === "pass" || val === "delayed" : val === "pass"
);
```

