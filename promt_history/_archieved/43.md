

# Prompt 43 — Experiment Health Layer

Goal: add a **health and safety layer** on top of the experimentation engine.

Prompt 42 introduced exposure telemetry and diagnostics data.
Prompt 43 uses that data to detect **experiment integrity problems** and
prevent misleading conclusions (false winners, skewed traffic, inactive variants).

This layer does **not change routing behaviour**. It only evaluates the
health of a running or decided experiment.

---

# Health Checks

The following checks are evaluated for each experiment.

## 1. Traffic Imbalance Detection

Using exposure counters from KV:

```
actual_share = exposures_variant / total_exposures
```

Compare against configured weight.

```
expected_share = weight / 100
```

If the difference exceeds 10 percentage points:

```
|actual_share − expected_share| > 0.10
```

Flag the experiment:

```
⚠ Traffic imbalance
```

This condition commonly occurs when:

- sticky sessions dominate traffic
- winner mode is active
- bots repeatedly hit one variant

The warning is informational and does not stop routing.

---

## 2. Minimum Sample Size Guard

Winner decisions should not be trusted when exposure volume is too low.

Basic rule:

```
minimum_exposures_per_variant = 50
```

If any variant has fewer exposures:

```
⚠ Sample size too small
```

Purpose:

Prevent early “false winner” interpretation.

This does not block experiment execution; it only informs the operator.

---

## 3. Inactive Variant Detection

Detect when a variant receives no traffic.

Condition:

```
variant_exposures == 0
```

Warning:

```
⚠ Variant inactive
```

Possible causes:

- misconfigured weight
- routing bug
- experiment already decided

---

## 4. Winner Mode Indicator

When an experiment has a decided winner:

```
experiment.status == "decided"
```

Admin UI must display:

```
Winner mode active
Traffic routed to winner
```

This clarifies why distribution may diverge from configured weights.

Example display:

```
Winner: ab-test-1-igbio
Mode: winner routing
Traffic → igbio (100%)
```

---

# Admin Display Model

Each experiment health card should expose:

```
Experiment: ab1

Status: running | decided

Health indicators:

⚠ Traffic imbalance
⚠ Sample size too small
⚠ Variant inactive

or

✓ Experiment healthy
```

Warnings are cumulative.

---

# Evaluation

Prompt 43 introduces **experiment observability** without changing
experiment routing or statistical logic.

The health layer helps operators quickly identify problems that would
otherwise lead to incorrect interpretation of results.

Key benefits:

- reduces false winner interpretation
- surfaces routing anomalies
- improves experiment reliability

# Summary — Prompt 43 Implementation

## Single file changed: `functions/admin/experiments.js`

No backend changes. All health data derived client-side from the existing `/api/experiments` payload (`variants[].exposures`, `variants[].weight`, `state`, `stored_winner`).

---

## New: Experiment Health card

Inserted between Lifecycle Controls and the Variant Performance table.

### `renderHealth(variants, lifecycleState, storedWinner)`

Evaluates four checks in order (cumulative — all applicable checks shown simultaneously):

| # | Check | Condition | Output |
|---|---|---|---|
| 1 | Inactive variant | `v.exposures === 0` | ⚠ Variant inactive — `<slug>` has received no traffic |
| 2 | Sample size guard | `0 < exposures < 50` | ⚠ Sample size too small — fewer than 50 exposures |
| 3 | Traffic imbalance | `\|actual% − weight%\| > 10` (RUNNING/PAUSED only) | ⚠ Traffic imbalance |
| 4 | Winner mode | state DECIDED/ARCHIVED && storedWinner | 🏆 Winner mode active — traffic routed to `"<slug>"` |

When no warnings: `✓ Experiment healthy` (green).

```js
var MIN_SAMPLE = 50;  // separate from MIN_EXPOSURE = 30 (chart threshold)
```

---

## Updated: `renderDistribution(variants, lifecycleState)`

New `lifecycleState` parameter. In DECIDED/ARCHIVED states:
- Per-row imbalance styling disabled (`isImbalance` always `false`)
- Warning strip replaced with: `ℹ Winner routing active — distribution reflects winner enforcement, not configured weights`

Prevents a false alarm when winner-mode routing concentrates all traffic on one variant (expected, not a bug).

---

## CSS added

`.health-item`, `.health-item.h-warn` (amber), `.health-item.h-info` (green), `.health-item.h-ok` (green bold), `.health-icon`

---

## Design decisions

- **`MIN_SAMPLE = 50` vs `MIN_EXPOSURE = 30`**: separate constants — `MIN_EXPOSURE` gates the chart (needs any data); `MIN_SAMPLE` is the statistical reliability threshold. Different concerns.
- **Inactive check fires even at 0 total traffic**: if the experiment has no traffic at all, every variant is flagged inactive — this surfaces the "experiment configured but not running" problem explicitly.
- **Traffic imbalance skipped in winner-routing states**: in DECIDED/ARCHIVED the distribution intentionally diverges; the winner mode indicator (Check 4) replaces the imbalance warning as the relevant signal.
- **Warnings cumulative**: multiple problems can coexist; showing all simultaneously is more actionable than showing only the most severe.
