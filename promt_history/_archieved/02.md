## NON-NEGOTIABLE SYSTEM INVARIANTS

### 1) Canonical analytics identity is immutable
Historical analytics records already contain canonical slugs such as:
- `album-launch-igbio`
- `album-launch-igstory`
- `album-launch-yt`

Analytics events MUST contain canonical slugs ONLY.
Alias strings MUST NEVER appear in analytics payloads.

### 2) URL surface is decoupled from analytics identity
Public URLs may change, but internal analytics identity must remain stable.
Routing translates public URL → canonical slug.

### 3) Public URL grammar is extremely simple
Only these two public patterns exist:
- `/<alias>`
- `/<alias>/<modifier>`

Examples:
- `/album`
- `/album/ig`
- `/album/yt`

Anything else (3+ segments, empty alias, etc.) MUST return **404**.

### 4) Alias maps to campaign_id, not canonical slug
Alias resolves to a **campaign_id**.
Campaign registry defines channels and default.
Canonical slug is always:

`canonical_slug = campaign_id + "-" + channel_id`

### 5) Deterministic, O(1) resolution only
No prefix scans.
No list scans.
No iterating over large sets.
Only direct KV lookups.

### 6) No modifier fallback
If modifier is unknown, return **404**.
Never silently fall back to base alias.

### 7) Canonical slug becomes single source of truth BEFORE analytics
After resolution, only canonical_slug may flow into rendering and analytics.
Alias/modifier must be cut at the boundary.

## STORAGE (SEPARATE KV NAMESPACES)

We use three KV namespaces for operational clarity:

### ALIAS_REGISTRY
Stores alias bindings (minimal, stable schema).
- `alias:<alias>` → `campaign_id`

Optional overrides (rare escape hatch; must be clearly separated):
- `alias_override:<alias>@<modifier>` → `canonical_slug`

Notes:
- Override must not conflict with normal alias keys.
- Override is checked ONLY for `/<alias>/<modifier>`.

### CAMPAIGN_REGISTRY
Stores campaign definitions.
- `campaign:<campaign_id>` → JSON record:

Required fields:
- `campaign_id: string`
- `default_channel: string`
- `channels: object | array` (authoritative channel ids)
- `modifier_map: object` (modifier synonym → channel_id)
- `routing_revision: integer` (monotonic; increments on default/mapping changes)
- `updated_at: ISO string`
- `updated_by: string | null`

Modifier synonyms example:
- `ig`, `insta`, `instagram` → `igbio`
- `yt`, `youtube` → `yt`

### HUB_CONFIG
Stores hub rendering config keyed by canonical slug.
- `hub:<canonical_slug>` → JSON config

## ROUTING RESOLUTION PIPELINE (MUST MATCH EXACTLY)

For every request:

1) Normalize path
- lowercase
- trim
- strip trailing slash
- reject non-ASCII or characters outside `[a-z0-9-]` for alias and modifier

2) Parse segments
- Accept only 1 or 2 segments
- 0 segments or 3+ segments → 404

3) Extract
- alias = segment 1
- modifier = segment 2 (optional)

4) If modifier exists, check override (fast path)
- KV get: `ALIAS_REGISTRY["alias_override:" + alias + "@" + modifier]`
- If found: canonical_slug = override value
  - Validate canonical_slug format
  - Proceed to hub config + render + analytics

5) Alias lookup
- KV get: `ALIAS_REGISTRY["alias:" + alias]` → campaign_id
- If missing → 404 + ops log

6) Campaign registry lookup
- KV get: `CAMPAIGN_REGISTRY["campaign:" + campaign_id]`
- Validate:
  - campaign_id matches
  - default_channel exists in channels
  - if modifier exists: modifier_map contains modifier
  - modifier_map target channel exists in channels

7) Channel resolution
- if no modifier: channel_id = default_channel
- if modifier: channel_id = modifier_map[modifier]
- if modifier missing in map → 404 + ops log

8) Canonical slug creation
- canonical_slug = campaign_id + "-" + channel_id

9) Boundary enforcement
From this point forward, ONLY canonical_slug may be used.
Alias and modifier must NOT be passed into:
- hub renderer
- analytics writer
- click handlers

10) Hub config
- KV get: `HUB_CONFIG["hub:" + canonical_slug]`

11) Render
- Render the hub page for canonical_slug

12) Marketing analytics write
- Write clickstream events only with canonical_slug:
  - `slug: canonical_slug`
  - `link_id`
  - `dest_host`
  - other event fields

No alias/modifier in marketing analytics.

### Architecture decisions

**Single catch-all (`[[path]].js`)**
Cloudflare Pages Functions resolves more-specific routes first (ig.js, c/[slug].js, api/*, etc.), so `[[path]]` cleanly handles all unmatched public alias paths without any route precedence collisions. No `[alias].js` + `[alias]/[modifier].js` overlap.

**In-memory TTL cache (`kv-cache.js`)**
Module-level `Map` that persists for the lifetime of the isolate. `cacheGet` / `cacheSet` with configurable TTL (default 60 s via `ALIAS_CACHE_TTL_MS` env var). Hard cap of 2 000 entries as an OOM safety valve. Cache keys are namespaced by type (`alias:`, `campaign:`, `hubcfg:`, `override:`, `legacy_slug:`, `global_cfg:`).

**Ops telemetry (`ops-telemetry.js`)**
`emitOps(env, event, fields)` writes to `LINKHUB_OPS` Analytics Engine dataset — entirely separate from the marketing clickstream (`LINKHUB_EVENTS`). Always emits a structured JSON `console.log` / `console.error` in parallel (Logpush-compatible). Failures in the telemetry path are silently discarded and never affect routing.

**Resolution pipeline (`alias-router.js`)**
Implements all 12 spec steps:
1. Path normalisation + `[a-z0-9-]` character validation in `parsePath()`
2. Override fast-path (direct `alias_override:<alias>@<modifier>` lookup, bypasses full pipeline)
3. Alias → campaign_id lookup (supports plain string or JSON object value)
4. Campaign record validation (campaign_id match, default_channel in channels, modifier_map target in channels)
5. Channel resolution (default or modifier_map lookup — no silent fallback on unknown modifier)
6. `canonical_slug = campaign_id + "-" + channel_id`
7. Hub config load: `HUB_CONFIG["hub:<slug>"]` → fallback `LINKHUB_SLUGS["<slug>"]` (backward compat)

**Canonical slug boundary**
`alias` and `modifier` are not referenced after `canonicalSlug` is constructed. `renderHub` receives `contextId: canonicalSlug` only — alias strings can never reach analytics payloads.

### Error semantics

| Condition | HTTP | Ops event |
|---|---|---|
| Invalid path segments / chars | 404 | — (parsePath returns error) |
| Unknown alias | 404 | `route_fail_unknown_alias` |
| Unknown modifier | 404 | `route_fail_unknown_modifier` |
| Missing campaign record | 404 | `route_fail_registry_inconsistent` |
| campaign_id mismatch | 404 | `route_fail_registry_inconsistent` |
| Invalid default_channel | 404 | `route_fail_registry_inconsistent` |
| Modifier maps to nonexistent channel | 404 | `route_fail_registry_inconsistent` |
| resolveAlias throws unexpectedly | 404 | console.error |
| Route success | 200 | `route_success` |

Never returns 500 on the public surface.

### KV read budget (per request)

| Path | Max KV reads |
|---|---|
| `/<alias>` (cache warm) | 0 |
| `/<alias>` (cold) | 2 (alias + campaign) |
| `/<alias>/<modifier>` (cold, no override) | 3 (override miss + alias + campaign) |
| `/<alias>/<modifier>` (override hit, cold) | 1 |
| + hub config (cold) | +1 |
| + global config (cold) | +1 |

All paths O(1) — no prefix scans, no list operations.
