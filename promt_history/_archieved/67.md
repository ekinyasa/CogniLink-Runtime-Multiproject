Goal
Improve the Experiments admin UI and prepare the system for real purchase conversion tracking without changing the routing, telemetry, or KV architecture implemented in Prompt 66.

Important Constraints
- Do NOT change routing behaviour.
- Do NOT change telemetry counters or shard logic.
- Do NOT change KV namespace usage introduced in P66.
- All changes are limited to admin UI, experiment creation flow, and conversion pipeline preparation.

---

SECTION 1 — Experiments List Filtering

Problem
The Experiments dropdown currently lists every campaign/alias instead of only experiments.

Required change
The Experiments list must read only experiment configs.

Source of truth:

CAMPAIGN_REGISTRY
Keys:

ab_config:*

Implementation
Replace any logic that loads experiments from alias or campaign lists with:

CAMPAIGN_REGISTRY.list({ prefix: "ab_config:" })

UI behaviour
The Experiments dropdown should display:

experiment_alias
variants
state

Do not include campaigns without AB configs.

SECTION 2 — Create Experiment From Experiments Page

Add a "Create Experiment" form directly on the Experiments page.

Important

Form fields

experiment_alias

SECTION 3 — Variant Slug Selector Scope

Problem
The current selector allows choosing any slug from any campaign.

Required change
When a campaign is selected, the variant selector must only show slugs belonging to that campaign.

Rule

slug.startsWith(campaign)

Example

campaign = a65

allowed variants:

a65-ab-campaign-igbio
a65-ab-campaign-yt

This keeps analytics clean and prevents cross‑campaign contamination.

### Modified files

| File | Change |
|---|---|
| `functions/admin/experiments.js` | S1: `loadAliases()` → calls `/api/admin/experiments`, formats options as `alias — STATE`; S2: "Create Experiment" collapsible panel with full form; S3: campaign change triggers `loadSlugsForCampaign()` via `/api/admin/slugs`; S4: `Weight` + `Share` columns added to variant performance table |
| `functions/api/ab.js` | S5: `epsilon` + `strategy` fields passed through in PUT (preserved across updates, ignored by routing) |

---

### Section-by-section decisions

- **S1**: New `GET /api/admin/experiments` endpoint (not reuse of `/api/admin/aliases`) — aliases are campaign-level concepts, experiments are CAMPAIGN_REGISTRY `ab_config:*` records. Clean separation.

- **S2+S3**: Create form uses `PUT /api/ab` (create-or-replace). Campaign dropdown loaded from `/api/admin/aliases`. Slug dropdowns loaded lazily per campaign via `/api/admin/slugs?campaign=`. Form auto-suggests alias from campaign name.

- **S4**: `Weight` (configured %) and `Share` (actual % of total traffic) added as columns to the Variant Performance table. The existing Traffic Distribution card still shows the bar chart representation — both views now available.

- **S5**: `epsilon` + `strategy` fields preserved across updates via spread operator. Not sent unless explicitly provided. Routing code ignores unknown fields.

- **S6**: Guard returns 200 plain text (not redirect) when cookies missing — prevents `/t` from receiving a malformed conversion with empty `exp`/`v` params. `utm_campaign` / `utm_content` forwarded for future attribution dimension support.

- **S7**: `order_id` accepted in body, validated (string, max 128 chars), logged in `[convert]` log line. No KV storage — purely prep for Kartra webhook integration in a future prompt.
