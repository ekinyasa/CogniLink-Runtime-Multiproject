## Issue 1 — A/B routing ignores weights (`ab-router.js`)

**Root cause**: The epsilon-greedy exploration branch returned `config.variants[bucket % variants.length].slug` — pure uniform distribution. With `epsilon = 1.0`, **100% of traffic** took this path, making any 2-variant experiment appear as 50/50 regardless of stored weights.

**Fix**: Removed the early `return` inside the exploration branch. Both exploration and exploitation now fall through to the same cumulative-weight walk. 80/20 is now always 80/20. The epsilon gate logic (whether to explore) is preserved unchanged.

---

## Issue 2 — Conversion pings invisible to stats panel (`conversion.js`)

**Root cause**: `POST /api/experiment/conversion` wrote to `CAMPAIGN_REGISTRY` under key `conv:<alias>:<variant>`. The stats panel (`GET /api/experiments`) reads from `TELEMETRY_REGISTRY` under `exp:<alias>:<variant>:conversion:{shard}`. Different namespace + different key format — zero overlap.

**Fix**: Added `waitUntil(incrementExpCounter(env, alias, variant, "conversion"))` — a fire-and-forget write to `TELEMETRY_REGISTRY` using the exact sharded key format that `exp-counter.js`/`t.js`/`experiments.js` all agree on. The existing `CAMPAIGN_REGISTRY` write is kept for the response `total` field, so the API shape is unchanged.

---

## Issue 3 — Stopwatch fails to stop (`admin-renderer.js`)

**Root cause**: `swInterval` was never set to `null` after `clearInterval()`. A stale interval ID could survive a stop, and the start branch never defensively cleared before launching a new `setInterval`, so orphaned intervals could accumulate under any desync.

**Fix**: `swInterval = null` added after every `clearInterval()` call (stop branch + existing reset branch). Added `clearInterval(swInterval); swInterval = null;` at the top of the start branch as a defensive guard. `swRunning` is now the single source of truth; interval state always matches it.
