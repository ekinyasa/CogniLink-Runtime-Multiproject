## Campaign OS — Routing Activation & Compile Pipeline

### 1. Root Cause: ROUTE_TABLE was never populated

`compileRoutes()` existed in `functions/_shared/route-compiler.js` but was never triggered.
No endpoint called it, and it is not invoked automatically on deploy.
ROUTE_TABLE remained permanently empty → every public request returned 404.

The runtime router in `alias-router.js` correctly reads only from ROUTE_TABLE (single KV get).
The missing step was: an admin endpoint to run the compile.

---

### 2. Files created / modified

#### `functions/api/admin/compile-routes.js` — NEW

```
POST /api/admin/compile-routes
Authorization: Bearer <ADMIN_TOKEN>
Body: { "dryRun": true }  (optional)
```

Calls `compileRoutes(env, { dryRun, invalidateCache: true })`.
- `dryRun: true` → validates without writing ROUTE_TABLE (safe pre-check).
- `dryRun: false` (default) → compiles and writes all route entries.
- Returns 200 on success, 422 if compile has validation errors.

Response shape:
```json
{
  "ok": true,
  "written": 4,
  "compiled": 4,
  "dry_run": false,
  "errors": [],
  "skipped": [],
  "stats": { "campaign_aliases": 1, "slug_aliases": 1, "duration_ms": 38 }
}
```

---

#### `functions/_shared/route-compiler.js` — UPDATED

Two compilation phases now run in sequence:

**Phase A — Campaign aliases** (`alias:*` → campaign_id)

For each `alias:X` key in ALIAS_REGISTRY:
1. Reads campaign record from CAMPAIGN_REGISTRY.
2. Writes `route:X` → `campaign_id-default_channel`.
3. For each modifier in `modifier_map`: writes `route:X@modifier` → `campaign_id-channel`.

**Phase B — Slug aliases** (`slug_alias:*` → canonical_slug, direct)

For each `slug_alias:Y` key in ALIAS_REGISTRY:
1. Validates canonical_slug format.
2. Optionally checks LINKHUB_SLUGS: skips if slug not found or `isActive=false`.
3. Writes `route:Y` → canonical_slug.

Atomic: if ANY error in either phase, ROUTE_TABLE is NOT written.
Idempotent: safe to run any number of times.
Workers Cache is invalidated after every successful write.

Observability log per compile (console/Logpush only — no AE write):
```
[compile] { campaign_aliases, slug_aliases, routes_compiled, errors, skipped, dry_run, duration_ms }
```

#### `functions/api/campaign/index.js` — UPDATED

POST /api/campaign now accepts an optional `alias` field.

Flow:
1. Validates alias format via `validateAlias()`.
2. Parallel-checks global uniqueness: `alias:X` + `slug_alias:X` in ALIAS_REGISTRY.

### 3. ROUTE_TABLE schema

```
route:<alias>           → canonical_slug          (default channel)
route:<alias>@<modifier>→ canonical_slug          (modifier-specific channel)
```

All values are canonical slugs (`campaign_id-channel_id`).
Alias and modifier strings are never stored outside ROUTE_TABLE keys.

---

### 4. Routing activation

After running `POST /api/admin/compile-routes`:

| Request path | ALIAS_REGISTRY entry     | ROUTE_TABLE entry         | Canonical slug     |
|--------------|--------------------------|---------------------------|--------------------|
| `/iki`       | `alias:iki → iki-uc`     | `route:iki → iki-uc-igbio`| `iki-uc-igbio`     |
| `/bio`       | `slug_alias:bio → iki-uc-igbio` | `route:bio → iki-uc-igbio` | `iki-uc-igbio` |
| `/iki/ig`    | —                        | `route:iki@ig → iki-uc-ig`| `iki-uc-ig`        |
| `/unknown`   | —                        | (miss)                    | 404                |

Runtime flow per request (cold path):
1. `parsePath` → alias + modifier
2. Workers Cache lookup (O(1) in-memory)
3. `ROUTE_TABLE.get("route:<key>")` (single KV read on cache miss)
4. `validateCanonicalSlug` guard
5. Alias + modifier dropped → canonical_slug flows to rendering + analytics

No ALIAS_REGISTRY or CAMPAIGN_REGISTRY reads at runtime.

---

### 5. Invariants preserved

- canonical_slug is the only analytics identity — alias/modifier never reach analytics
- Routing is deterministic — same alias always produces same ROUTE_TABLE entry
- Routing is O(1) — single KV read per cold request, zero reads on cache hit
- Runtime reads only ROUTE_TABLE — ALIAS_REGISTRY and CAMPAIGN_REGISTRY are ops-only
- Admin operations never touch ROUTE_TABLE directly — only compile-routes writes it
