
    
# Prompt 69 — Experiment Creation Fix + Router Validation + Toolbar UX

We are continuing development of the Campaign OS experimentation system.

Context: Prompt 68 introduced the Experiments control surface (create experiment, rebalance traffic, epsilon‑greedy strategy, and winner promotion). Core functionality works, but testing revealed two blocking issues and one UI improvement.

Your task is to implement the following fixes and additions WITHOUT breaking existing routing grammar, public URLs, or current AB configs.

--------------------------------------------------
1. FIX: Experiment creation "alias_not_found"
--------------------------------------------------

Problem:
The Experiments page allows creating an experiment with a new alias, but backend validation fails because the alias does not yet exist in ALIAS_REGISTRY.

Desired behavior:
Creating an experiment from the Experiments page must automatically ensure the alias exists.

Implementation rules:

When creating a new experiment:

1) Check if alias exists in ALIAS_REGISTRY
2) If NOT present:
   - create the alias entry automatically
   - map it to the selected campaign

Sequence:

ensureAlias(alias, campaign)
writeExperimentConfig(alias, variants, weights, strategy)

The Routing tab must still be able to create aliases manually. Both flows must write to the SAME registry and stay synchronized.

Do NOT require the user to create the alias separately.

--------------------------------------------------
2. VALIDATE SLUG FILTERING (no regression)
--------------------------------------------------

Slug selection must only display slugs belonging to the chosen campaign.

Matching rule:

record.campaign === selectedCampaign

NOT prefix matching.

The UI must support:

• dynamic "Add Variant" rows
• max 10 variants
• weight validation (total = 100)

Do not regress this behavior.

--------------------------------------------------
3. TRAFFIC REBALANCE SAFETY
--------------------------------------------------

Ensure rebalance writes update immediately affect router behavior.

Requirements:

• rebalance uses PUT /api/ab
• router must read fresh config (no stale cache)
• experiment state must remain RUNNING

No schema changes needed.

--------------------------------------------------
4. OPTIONAL (only if trivial): Conversion Attribution Hook
--------------------------------------------------

Endpoint:

POST /api/experiment/conversion

Payload:

{
  alias,
  variant
}

Behavior:

increment conversion counter for that variant.

Do NOT implement session tracking yet.
This is only a basic manual conversion ping for thank‑you pages.

If this requires structural changes, skip it for now and leave a TODO comment.

--------------------------------------------------
5. Toolbar Stopwatch UX Change
--------------------------------------------------

Current HTML:

<div class="sw-toolbar" id="sw-toolbar">
  <span id="sw-display" class="sw-time">00:00.0</span>
  <button type="button" id="btn-sw-start" class="btn-sm">▶</button>
  <button type="button" id="btn-sw-reset" class="btn-ghost btn-sm">⟳</button>
</div>

Requested behavior:

• Remove separate start button
• Timer display itself becomes the start/pause toggle
• Reset button remains separate

New structure:

<div class="sw-toolbar" id="sw-toolbar">
  <button type="button" id="sw-display" class="sw-time">00:00.0</button>
  <button type="button" id="btn-sw-reset" class="btn-ghost btn-sm">⟳</button>
</div>

Behavior:

• clicking the timer toggles start/pause
• reset button resets to 00:00.0

No styling regressions.

Deliverables

1) experiment creation no longer throws alias_not_found
2) Experiments page can fully create and run tests
