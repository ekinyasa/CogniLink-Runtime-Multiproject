

Prompt 66 — KV Namespace Separation (Clean Cut)

Goal
Cleanly separate telemetry, dedup, experiment config, and alias registry data into their correct KV namespaces. Old keys can be ignored or deleted because they only contain test data. The system must keep working exactly as before while writing new data to the correct namespaces.

Important Rules
- Do NOT change public routes.
- Do NOT change experiment routing logic.
- Do NOT change URL grammar or query parameters.
- Only move where data is written/read in KV.

Target KV Responsibilities

ALIAS_REGISTRY
Used only for alias mapping.
Keys allowed:
  alias:<alias>

CAMPAIGN_REGISTRY
Used for experiment and campaign configuration.
Keys allowed:
  ab_config:<experiment>

HUB_CONFIG
No changes.

ROUTE_TABLE
No changes.

Create New KV Namespaces

TELEMETRY_REGISTRY
Stores counters and experiment telemetry.
Keys:
  exp:<exp>:<variant>:exposure:<shard>
  exp:<exp>:<variant>:click:<shard>
  exp:<exp>:<variant>:conversion:<shard>
  conv:alias:<exp>:<alias>
  conv:link:<exp>:<link_id>

DEDUP_CACHE
Stores temporary deduplication keys.
Keys:
  dedup:conv:<exp>:<variant>:<ua_hash>

Implementation Steps

1. Update wrangler.toml
Add KV bindings for the new namespaces:

[[kv_namespaces]]
binding = "TELEMETRY_REGISTRY"

[[kv_namespaces]]
binding = "DEDUP_CACHE"

2. Update conversion endpoint (/t)

Write the following keys to TELEMETRY_REGISTRY:

conv:alias:<exp>:<alias>
conv:link:<exp>:<link_id>
exp:<exp>:<variant>:conversion:<shard>

Write dedup keys to DEDUP_CACHE:

dedup:conv:<exp>:<variant>:<ua_hash>

3. Update experiment telemetry writes

All exposure, click, and conversion shard counters must be written to TELEMETRY_REGISTRY instead of ALIAS_REGISTRY.

Example:

exp:<exp>:<variant>:exposure:<shard>
exp:<exp>:<variant>:click:<shard>
exp:<exp>:<variant>:conversion:<shard>

4. Update analytics reads

Experiment analytics queries must read from TELEMETRY_REGISTRY.

Replace any reads like:

ALIAS_REGISTRY.list({ prefix: "exp:" })

with:

TELEMETRY_REGISTRY.list({ prefix: "exp:" })

Same change for:

conv:alias:
conv:link:

5. Remove telemetry usage from ALIAS_REGISTRY

ALIAS_REGISTRY must only contain:

alias:<alias>

Any telemetry writes to ALIAS_REGISTRY must be removed.

6. Optional cleanup (safe)

Because existing keys are only test data, you may delete telemetry-style keys from ALIAS_REGISTRY if convenient, but this is optional.

Expected Result

After this change:

Alias registry KV contains only:
  alias:<alias>

Telemetry KV contains:
  exp:* counters
  conv:alias:* counters
  conv:link:* counters


Dedup KV contains:
  dedup:conv:* keys

Experiment config KV contains:
  ab_config:* records

The public behavior of the system must remain identical.

No routing or campaign logic should change.

### KV namespace responsibilities after this change

| Namespace | Keys |
|---|---|
| `ALIAS_REGISTRY` | `alias:<alias>` only |
| `CAMPAIGN_REGISTRY` | `ab_config:<experiment>` only |
| `TELEMETRY_REGISTRY` | `exp:<exp>:<v>:<type>:<shard>`, `conv:alias:<exp>:<alias>`, `conv:link:<exp>:<link_id>` |
| `DEDUP_CACHE` | `dedup:conv:<exp>:<v>:<ua_hash>`, `exp_used:<nonce>` |

---

### Key decisions

- **`api/ab.js` requires both ALIAS_REGISTRY and CAMPAIGN_REGISTRY** in its PUT handler: ALIAS_REGISTRY is still needed for the `alias:<alias>` existence check (aliasExists guard), while `ab_config:*` reads/writes move to CAMPAIGN_REGISTRY. GET and DELETE only touch `ab_config:*` so they only require CAMPAIGN_REGISTRY.

- **`exp_used:*` replay keys** (written by `api/convert.js`) move to `DEDUP_CACHE` alongside the `dedup:conv:*` keys from `t.js` — both are replay-protection concerns with short TTLs.

- **No routing or public URL changes** — all changes are internal KV namespace routing only. Public behavior is identical.

- **wrangler.toml IDs are placeholders** (`REPLACE_WITH_*_ID`): run `wrangler kv namespace create TELEMETRY_REGISTRY` and `wrangler kv namespace create DEDUP_CACHE`, then fill in the printed IDs in both the default and `[env.production]` sections.
