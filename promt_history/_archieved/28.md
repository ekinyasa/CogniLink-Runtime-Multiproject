# Root-Cause Analysis

## Why it happened

The Prompt 23 v4 admin-renderer rewrite renamed the localStorage key from `"admin_token"`
to `"_sp_tok"` (an obfuscated name to avoid "admin" appearing in any browser-visible
surface). No migration code was added to copy an existing `"admin_token"` value.

After that deploy:
- **Active sessions that re-entered the token** were saved under `"_sp_tok"` → auth worked.
- **New browser sessions / cleared storage** found no `"_sp_tok"` → `token = ""` →
  `Authorization: Bearer ` (empty token) → `verifyToken()` returns false → 401.
- **Sessions still holding `"admin_token"`** never got written to `"_sp_tok"` →
  silent permanent auth failure until the operator manually re-entered the token.

The bug was intermittent (worked for active sessions, broken for new ones),
making it hard to diagnose. It became obvious after the Prompt 27 deploy triggered
fresh testing.

**Prompt 27 did not introduce this regression.** It was latent since Prompt 23.

# Security Assessment

## Auth flow diagram

```
localStorage["admin_token"]
       ↓  loadToken() at boot
  var token  (in-memory)
       ↓  authHeaders() on every apiFetch
  Authorization: Bearer <token>
       ↓  HTTPS → Cloudflare edge → Worker
  verifyToken(request, env)
  token === env.ADMIN_TOKEN
```

## Verdict: Appropriate for single-operator studio panel

| Property | Status | Notes |
|---|---|---|
| CSRF | ✅ Not possible | Bearer token in header, not cookie |
| Plaintext interception | ✅ Mitigated | TLS on Cloudflare Pages (HTTPS enforced) |
| XSS token theft | ⚠ Low risk | `esc()` sanitises all DOM writes; CSP not set |
| Timing attack on comparison | ⚠ Theoretical | `===` is not constant-time |
| Token rotation | ⚠ Manual | Change `ADMIN_TOKEN` env var + redeploy |
| Per-operator audit | ❌ None | Single shared secret |

## Recommended hardening (priority order)

### 1. Constant-time token comparison — Worker-side (low effort, high value)

`token === env.ADMIN_TOKEN` is susceptible to timing oracle attacks in theory.
`crypto.subtle.timingSafeEqual` is synchronous in Cloudflare Workers:

```js
// verifyToken — constant-time (replace current === comparison)
export function verifyToken(request, env) {
  const header = request.headers.get("Authorization") || "";
  if (!header.startsWith("Bearer ")) return false;
  const token = header.slice(7).trim();
  if (!token || !env.ADMIN_TOKEN) return false;
  const ta = new TextEncoder().encode(token);
  const tb = new TextEncoder().encode(env.ADMIN_TOKEN);
  if (ta.length !== tb.length) return false;
  return crypto.subtle.timingSafeEqual(ta, tb);   // sync in Workers
}
```

### 2. Lock the key name — already done in Prompt 28

`var TOKEN_KEY = "admin_token"` constant with a comment warning against renaming.
Any future rename is a single-line decision with visible intent.

### 3. Token rotation plan

Rotating `ADMIN_TOKEN` (via Cloudflare Pages environment variables) immediately
invalidates all active sessions — operators must re-enter the new token on next
page load. This is the correct revocation path for bearer-token auth.

### 4. CSP header (optional)

The panel uses an inline IIFE (`<script>…</script>`), so a strict Content-Security-Policy
would require `unsafe-inline` — limiting its benefit. Refactoring to an external script
file would enable `script-src 'self'` and eliminate that bypass.
