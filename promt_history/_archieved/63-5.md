CLAUDE ANSWER
Here is the complete diagnosis based on the actual routing code.

---

## 1. Entropy source for variant selection

**Deterministic hash of the CF-Ray header.**

```js
// [[path]].js line 207
const requestId = request.headers.get("cf-ray") || crypto.randomUUID?.() || "";

// ab-router.js selectABVariant()
const hexAll = String(requestId || "").replace(/[^0-9a-f]/gi, "") || "00000000";
const hex8   = hexAll.slice(-8) || "0";
const bucket = parseInt(hex8, 16) % 100;     // 0–99
```

Cloudflare assigns a unique CF-Ray per HTTP request (e.g. `7e06e33afe62b234-FRA`). Non-hex chars (airport code letters) are stripped before taking the last 8 hex chars. `Math.random()` is **never called**. In local dev / wrangler, CF-Ray is absent → `crypto.randomUUID()` is the fallback.

---

## 2. Is routing sticky per visitor?

**Yes — via cookie, not via the hash.**

```js
// experiment-router.js
const cookieName    = "exp_" + alias;
const cookieVariant = readCookie(request, cookieName);

if (cookieVariant && validSlugs.includes(cookieVariant)) {
  finalSlug = cookieVariant;          // ← hash never touched
  isNewAssignment = false;
} else {
  finalSlug = selectABVariant(experimentConfig, requestId);  // ← hash used here
  isNewAssignment = true;
}
```

The cookie (`exp_<alias>`, 30-day Max-Age, SameSite=Lax; Secure) is checked **first**. If it exists and contains a valid slug, `selectABVariant()` is **never called**. The CF-Ray only matters for first-time visitors (no cookie) or requests that explicitly send no cookie.

## 4. Is a curl loop from the same machine a valid test?

**Partially — it depends on whether a cookie jar is used.**

- **Without cookie jar** (`-c`/`-b` flags absent): each request has no `Cookie:` header → routing falls into `selectABVariant()` every time. Each request independently picks a variant based on its unique CF-Ray. ✅ **Valid test.**

- **With a cookie jar**: the first response sets `exp_<alias>=variant-A` (for example). All subsequent requests send that cookie → `cookieVariant` matches → router skips `selectABVariant()` and returns variant A **100% of the time**. ❌ **Completely invalid** — would show 100/0, not 50/50.

Since the observations show 64/36 and 68/32 (not 100/0), the curl tests were correctly run **without** a cookie jar. The test methodology is valid.

---

## 5. How to generate a valid curl-based traffic simulation

**For production (hitting real Cloudflare edge):**

```bash
# Cloudflare assigns a unique CF-Ray for every inbound request automatically.
# Do NOT use -c (cookie write) or -b (cookie read).
for i in $(seq 1 500); do
  curl -s -o /dev/null -w "%{http_code}\n" https://yourdomain.com/alias
done
```

No special headers needed. Each request gets its own CF-Ray from the edge. The distribution over 500+ requests will converge to the configured weights.

**For local dev (wrangler pages dev, no CF-Ray):**

CF-Ray is absent → falls back to `crypto.randomUUID()`, which is fine. But if you want to inject controlled entropy:

```bash
for i in $(seq 1 500); do
  RAY="$(openssl rand -hex 8)-TST"
  curl -s -o /dev/null -H "cf-ray: $RAY" http://localhost:8788/alias
done
```

**What must NOT vary between requests (to keep the test clean):**
- The alias path — keep it the same
- No cookie header (`-H "Cookie:"` would interfere)

**What must NOT be constant across requests:**
- The CF-Ray (automatically varies in prod; inject random values in local dev)

## 6. Root cause of 80/20 → ~64/36 and 90/10 → ~68/32

**Answer: (A) — the epsilon-greedy sampler was mixing uniform routing into the weighted selection.**

The math is exact. Solve for ε from both observations using the formula:

```
observed_A = (1 - ε) × configured_A + ε × 50
```

| Config | Observed | Solved ε |
|--------|----------|----------|
| 80 / 20 | 64 / 36 | ε = (80 − 64) / (80 − 50) = **0.533** |
| 90 / 10 | 68 / 32 | ε = (90 − 68) / (90 − 50) = **0.550** |

Both observations point to **ε ≈ 0.53–0.55**, consistent with a stored `epsilon` of ~0.5 (the bandit default) plus small sample noise.

The pre-fix code in the epsilon-greedy exploration branch:
```js
// bucket % variants.length = uniform distribution for 2 variants
return config.variants[bucket % config.variants.length].slug;
```
With ε=0.5, 50% of requests went through uniform (50/50) and 50% through weighted routing. The resulting blend:

```
80/20 config, ε=0.5:  0.5 × 50 + 0.5 × 80 = 65%  (observed 64% — 1% noise)
90/10 config, ε=0.5:  0.5 × 50 + 0.5 × 90 = 70%  (observed 68% — 2% noise)
```

Both expected values match the observations within plausible sample-size variance. The convergence toward 50/50 is not random; it is the mathematical signature of blending with a uniform distribution at probability ε.

**Options B (test methodology) and C (stale cache) can be ruled out:**
- B: The curl tests correctly skipped cookies, and CF-Ray varied per request. The methodology was sound.
- C: Stale cache would produce the OLD weight set exactly (e.g., 50/50 if the original config was 50/50), not a blend. The observations show a continuous blend — not a hard 50/50 step — which is only possible if both code paths were active simultaneously.
