# Prompt 26 — Alias A/B Routing (Traffic Intelligence Layer — Phase 1)

Campaign OS routing, telemetry, diagnostics and traffic memory layers are now stable.

This prompt introduces the **first Traffic Intelligence capability: deterministic alias A/B routing**.

The goal is to allow a single alias to distribute traffic between multiple canonical slugs using a fixed weight split.

Example:

/launch

may route traffic as:

50% → launch-youtube
50% → launch-ig

This allows controlled channel experiments without changing external links.

Important principles:

• Deterministic routing
• No redirect loops
• No impact on existing single-slug aliases
• Telemetry must record the final routed slug

Do NOT modify existing KV schema used by basic routing unless strictly necessary.

# SECTION A — Architecture Explanation

## Current alias resolution flow (before Prompt 26)

```
GET /<alias>[/<modifier>]
  │
  ├─ parsePath()             → { alias, modifier }
  ├─ resolveAlias()          → { canonicalSlug, cacheHit }
  │     ├─ Workers Cache lookup
  │     ├─ ROUTE_TABLE KV lookup (on miss)
  │     └─ emits ALIAS_CLICK + (old) TRAFFIC_MEMORY
  │
  └─ [[path]].js             → loadHubConfig(canonicalSlug) → renderHub(canonicalSlug)
```

## Where A/B routing is inserted

After `resolveAlias()` returns `canonicalSlug` and before `loadHubConfig()`, inside `[[path]].js`. This is the only safe insertion point because:

- `alias-router.js` must remain routing-only (no rendering decisions)
- `[[path]].js` is the boundary where `alias` and `modifier` are dropped
- `finalSlug` (the A/B variant) replaces `canonicalSlug` only for rendering — ROUTE_TABLE is never modified

## New flow (Prompt 26)

```
GET /<alias>[/<modifier>]
  │
  ├─ parsePath()
  ├─ resolveAlias()          → { canonicalSlug }   (TRAFFIC_MEMORY removed from here)
  │
  ├─ loadABConfig(alias)     → config or null       (ALIAS_REGISTRY, 60 s in-memory cache)
  │     └─ if config: selectABVariant(config, requestId) → finalSlug
  │
  ├─ emitOps(AB_SELECTED)    (only when A/B active)
  ├─ emitOps(TRAFFIC_MEMORY) (always; records finalSlug)
  │
  └─ loadHubConfig(finalSlug) → renderHub(finalSlug)
```

## Deterministic selection method

```
hex    = requestId.replace(/[^0-9a-f]/gi, "").slice(-8) || "0"
bucket = parseInt(hex, 16) % 100   →  0–99

Walk variants by cumulative weight → return slug of first variant
where bucket < cumulative
```

`requestId` = Cloudflare cf-ray header (or `crypto.randomUUID()` in local dev). cf-ray is unique per request and includes hex chars, making the distribution uniform across 100 buckets. The last 8 chars are used to avoid bias from the cf-ray datacenter prefix.

# SECTION B — Design

## Config storage

`ALIAS_REGISTRY["ab_config:<alias>"]` — JSON:

```json
{
  "variants": [
    { "slug": "launch-youtube", "weight": 50 },
    { "slug": "launch-ig",      "weight": 50 }
  ],
  "updatedAt": "2026-03-10T..."
}
```

Config is stored in `ALIAS_REGISTRY` (not `ROUTE_TABLE`) to keep routing structure unchanged.

## Cache strategy

In-memory sentinel pattern (kv-cache.js):

- Config present → cached for 60 s
- No config → `{ _no_ab_config: true }` sentinel cached for 60 s
- Aliases without A/B config: one KV read per isolate lifetime, then pure in-memory

## Safety constraints satisfied

- `compileRoutes()` / `ROUTE_TABLE` untouched — A/B routing is post-resolution
- `alias-router.js` unchanged in structure — only TRAFFIC_MEMORY note added
- No redirect loops — `finalSlug` is used directly for rendering, not fed back into `resolveAlias()`
- Modifier routing still works — `resolveAlias()` handles modifier fallback before A/B kicks in

# Implementation Summary

## Root cause of TRAFFIC_MEMORY migration

`alias-router.js` only knows the ROUTE_TABLE base slug. When A/B routing selects a different variant, `alias-router.js` cannot know it. Moving TRAFFIC_MEMORY to `[[path]].js` — after `selectABVariant()` — ensures it always records the slug the user actually sees, making experiment analysis accurate.

## New event: AB_SELECTED

Emitted once per request when an alias has an active A/B config. Stores both `base_slug` and `variant_slug` in `detail`, enabling:

```sql
-- Variant distribution for an alias:
SELECT blob6 AS detail_json, COUNT()
FROM linkhub_ops_events
WHERE index1 = 'ab_selected' AND blob1 = 'launch'
```

## In-memory cache sentinel

`loadABConfig()` stores `{ _no_ab_config: true }` for aliases with no config. Because `kv-cache.cacheGet()` returns `null` for both "cache miss" and expired entries, a plain `null` cannot be cached — the sentinel distinguishes "definitively no config" from "not yet checked". Aliases without A/B config pay at most one KV read per isolate lifetime.
