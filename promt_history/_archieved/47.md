

# Prompt 47 — Multi-Armed Bandit Routing + Lifecycle Expansion

Goal: move Campaign OS from static A/B experimentation into adaptive traffic optimization, while also formalizing experiment lifecycle states.

Prompt 46 stabilized the experiment engine and conversion pipeline.
Prompt 47 introduces two major upgrades:

1. Multi-armed bandit routing
2. Experiment lifecycle expansion

These changes are the next logical step after stabilization.

---

## 1. Multi-Armed Bandit Routing

Current behavior:

- variants use static weighted routing
- traffic remains fixed until manual or explicit winner decision

Replace this with adaptive bandit logic.

### Requirements

- replace static weighted routing with dynamic traffic allocation
- implement Thompson sampling variant selection
- maintain an exploration floor of 5–10%

### Expected behavior

At the start of an experiment:

A → 50%
B → 50%

As conversions are observed:

A → 30%
B → 70%

Later:

A → 10%
B → 90%

But never drop a variant below the exploration floor.

Purpose:

- reduce wasted traffic
- learn faster from small samples
- shift traffic toward better-performing variants automatically

---

## 2. Experiment Lifecycle Expansion

Current lifecycle is too shallow.

Expand to:

DRAFT
RUNNING
DECIDED
ARCHIVED

### Rules

- DRAFT experiments do not receive live traffic
- RUNNING experiments use bandit routing
- DECIDED experiments route directly to winner
- ARCHIVED experiments are excluded from active routing

### Requirements

- enforce strict state transition rules
- prevent traffic from reaching archived experiments
- keep decided experiments stable and deterministic

---

## 3. Winner Promotion Automation

Once an experiment is confidently decided:

- automatically promote the winner to direct campaign routing
- bypass experiment routing after decision
- preserve attribution parameters

This removes stale experiment overhead and locks in the best-known variant.

---

## 4. Auto Archive

Add automatic archive support for stale experiments.

### Requirements

- archive experiments after an inactivity window
- preserve a stats snapshot before archive
- prevent stale experiments from polluting active router state

---

## 5. Constraints

- keep backward compatibility with existing experiment configs
- do not break current routing URLs
- do not remove existing counters or analytics keys yet
- bandit routing must still write exposure and conversion counters

---

## Expected Result

After this prompt:

- Campaign OS no longer behaves like a static A/B tool
- traffic automatically shifts toward higher-performing variants
- experiment lifecycle becomes explicit and enforceable
- decided winners can be promoted and retired cleanly
- stale tests stop polluting the routing layer

## Implementation Summary

### Files Created

**`functions/_shared/bandit.js`** (new)
- `betaSample(alpha, beta)` — Beta distribution sampling via Marsaglia-Tsang Gamma method
- `thompsonSelect(variants)` — single-draw Thompson sampling; selects variant with highest Beta draw
- `computeBanditWeights(variants, floorPct=5)` — computes integer weights (sum=100) with exploration floor via largest-remainder method
- `EXPLORATION_FLOOR_PCT = 5` — minimum traffic per variant (5%)

**`functions/api/experiment/bandit-update.js`** (new)
- `POST /api/experiment/bandit-update` — reads counters, computes alpha/beta posteriors, writes updated weights + `last_active_at` + `stats_snapshot`
- auto-archive: if no new exposures in 14 days → archive with preserved stats snapshot
- `dry_run: true` body param — preview weights without writing to KV
- only applies to RUNNING experiments (returns 400 for other states)

**`functions/api/experiment/activate.js`** (new)
- `POST /api/experiment/activate` — DRAFT → RUNNING transition via `applyLifecycleTransition`
- stamps `created_at` if absent (records activation time)

### Files Modified

**`functions/_shared/ab-router.js`**
- added `"DRAFT"` to `EXP_STATES` array
- added `import { thompsonSelect } from "./bandit.js"`
- `selectABVariant()`: bandit mode activates when all variants carry numeric `alpha`/`beta` (set by bandit-update); falls back to deterministic bucket routing for static configs

**`functions/[[path]].js`**
- DRAFT branch: when `expState === "DRAFT"`, skip all A/B logic entirely — serve canonical slug, no counters, no cookie, `abActive` stays false

**`functions/api/ab.js`**
- new experiments start as `state: "DRAFT"` (not RUNNING)
- existing experiments preserve their stored state on update: `existingConfig ? (existingConfig.state ?? "RUNNING") : "DRAFT"`

**`functions/api/experiment/_lifecycle.js`**
- updated state machine comment to document DRAFT → RUNNING (activate) transition

**`functions/admin/experiments.js`**
- CSS: `.sc-badge.b-draft` (#6366F1 indigo), `.status-card.sc-draft` (lavender bg), dark-mode variants
- HTML: `btn-lc-activate` (▶ Activate) and `btn-lc-bandit` (↻ Update Bandit Weights) buttons in lifecycle controls

- `renderDashboard`: DRAFT added to displayState logic; `lifecycleState === 'DRAFT'` shows only Activate button; RUNNING shows Activate, Pause, Archive, Bandit Update buttons; DRAFT badge label = `DRAFT — NOT LIVE`

### Architecture Decisions

**Thompson Sampling implementation**: stored alpha/beta per variant in AB config (updated by `bandit-update`) + per-request Beta draws at routing time. No extra KV reads — config is already cached (60s TTL). Backward compatible: falls back to static weight routing if no alpha/beta present.

**Auto-archive trigger**: `bandit-update` endpoint checks `last_active_at`. If total exposures haven't increased since last call AND inactivity > 14 days → archive with stats snapshot. Prevents stale experiments from polluting active router state.

**DRAFT state**: new experiments created via `PUT /api/ab` now start as DRAFT. Traffic gate is enforced in `[[path]].js` — DRAFT configs are loaded but completely ignored (serve canonical slug). Explicit `POST /api/experiment/activate` required to begin routing.

**Winner promotion**: unchanged from P44/P45 — `persistDetectedWinner` in `experiments.js` auto-transitions to DECIDED; admin `promote` action transitions to ARCHIVED with winner set. DECIDED/ARCHIVED fast-paths in `[[path]].js` route directly to winner.

### Constraints Met

- Backward compat: existing configs without `state` field default to RUNNING via `getExpState()` fallback
- No URL changes: routing URLs unchanged
- Counters preserved: bandit routing still writes exposure/conversion counters (RUNNING branch unchanged)
- Exploration floor: `EXPLORATION_FLOOR_PCT = 5` — no variant drops below 5% traffic
