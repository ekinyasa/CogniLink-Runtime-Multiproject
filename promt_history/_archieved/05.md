### 1. Admin UI — `functions/_shared/admin-renderer.js`

#### Slug form (Campaign Links tab)

New field added between slug input and UTM preset selector:

```
Route Alias  (optional — short public route, e.g. "bio")
[___________]
```

- On blur: calls `GET /api/admin/check-alias?value=<alias>`
- Shows real-time status below the field:
  - `✓ Available` (green)
  - `Conflict: already used as slug alias → iki-uc-igbio` (red)
  - `Invalid format. Use lowercase letters, numbers, hyphens (max 48 chars).` (red)
  - `Current alias` (neutral — shown when editing and value matches loaded alias)
- `alias` field included in POST payload (create) and PUT payload (update)
- On edit load: alias populated from `data.alias`, marked as `data-original-alias` for skip-self detection
- On `resetForm()`: alias input cleared, status hidden

#### Campaign create (inline form)

New alias input added inside the "Create new campaign" box:

```
[ new-campaign-2026  ] [ Create ]
[ alias (optional, e.g. iki)    ]
```

- On blur: calls check-alias with the same uniqueness logic
- Alias sent as part of `POST /api/campaign` body if provided
- Shows note from API response (e.g. "Alias saved. Run compile-routes.") or warning if alias write failed
- Alias input cleared after successful campaign creation

#### Campaign list (Campaigns tab)

Each campaign item now shows:
- Current alias in meta row: `campaign-name · 2026-03-05 · alias: iki`
- New "Alias" button in actions row
- Clicking "Alias" reveals an inline edit row:
  ```
  [ current-alias ] [ Save ] [ Cancel ]
  ```
- On Save: calls `PATCH /api/campaign/:name` with `{ alias: newValue }`
- On success: updates local `campaigns` cache, re-renders list
- Alias blur validation wired (lazy, on first reveal)

#### Routing tab (new, 4th tab)

New "Routing" tab added to tab bar. Contains:

```
Compile Routes
─────────────────────────────────────────
After adding aliases, compile to populate ROUTE_TABLE and activate public routing.
Routing is not active until you run Compile Routes.

[ Dry Run ]  [ Compile Now ]

┌─────────────────────────────────────────┐
│ Result          ✓ Success               │
│ Routes compiled 4                       │
│ Routes written  4                       │
│ Campaign aliases 1                      │
│ Slug aliases    1                       │
│ Errors          0                       │
│ Skipped         0                       │
│ Duration        38 ms                   │
```

- **Dry Run** → `POST /api/admin/compile-routes { dryRun: true }` — validates without writing ROUTE_TABLE
- **Compile Now** → `POST /api/admin/compile-routes { dryRun: false }` — writes ROUTE_TABLE and activates routing
- Both show full result table with `ok`, `compiled`, `written`, `errors.length`, `skipped.length`, `stats.*`, `duration_ms`

### 2. API — `functions/api/slug/index.js` (POST)

`alias` is now stored in the slug record (alongside `isActive`, `createdAt`, etc.):

```json
{ "slug": "iki-uc-igbio", "alias": "bio", "campaign": "iki-uc", ... }
```

This enables the admin UI to display/edit the current alias on the Edit form without scanning ALIAS_REGISTRY.

---

### 3. API — `functions/api/slug/[slug].js` (PUT)

Now accepts optional `alias` field:

- `"alias" not in body` → no change to alias
- `alias: "new-value"` → validate format, check global uniqueness (skip if same as current), delete old `slug_alias:<old>`, write `slug_alias:<new>` to ALIAS_REGISTRY
- `alias: null` or `alias: ""` → clear alias; delete `slug_alias:<old>` from ALIAS_REGISTRY
- Non-fatal alias write failure → slug updated, response includes `warning`
- Success with alias change → response includes `note: "Alias saved. Run POST /api/admin/compile-routes to activate routing."`

---

### 4. API — `functions/api/campaign/[name].js` (PATCH)

Previously only accepted `{ isActive: boolean }`. Now accepts:

- `{ isActive: boolean }` — archive/restore only (backward compatible)
- `{ alias: "new-value" | null }` — alias change only
- `{ isActive: boolean, alias: "…" }` — both at once

Alias transition logic:
- Delete old `alias:<old>` from ALIAS_REGISTRY if alias changed
- Write `alias:<new>` → campaign_name to ALIAS_REGISTRY
- Update `alias` field in campaign record (LINKHUB_CAMPAIGNS)
- Non-fatal alias write failure → campaign updated, response includes `warning`

### 5. Alias UX behavior (all cases)

| Scenario | UI behavior |
|----------|-------------|
| New slug, no alias | `alias` field blank → sent as `null` → no ALIAS_REGISTRY entry |
| New slug, alias "bio" | `alias: "bio"` sent → `slug_alias:bio = iki-uc-igbio` → note to compile |
| Edit slug, alias unchanged | `data-original-alias` matches → status shows "Current alias" → PUT includes same alias → backend skips (no-op) |
| Edit slug, alias changed | Blur triggers check-alias → if available, PUT sent → old removed, new written |
| Edit slug, alias cleared | `alias: null` sent → `slug_alias:<old>` deleted |
| Alias conflict | check-alias returns `available: false, conflict` → UI shows exact conflict, blocks submit |
| Campaign alias | Same flow via PATCH /api/campaign/:name with `{ alias }` |
