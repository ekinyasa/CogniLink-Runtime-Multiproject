# ✅ Implementation — P82

## Root cause (confirmed)

`loadABConfig` in `ab-router.js` cached valid AB configs for 60 seconds (`AB_CACHE_TTL_MS`). After a bandit rebalance:

- The rebalancing isolate called `cacheDelete(AB_CACHE_PREFIX + alias)` — only clears its own in-memory cache
- All other edge isolates continued to serve the old 50/50 weights from their in-memory cache for up to 60 more seconds
- On a busy edge deployment with many isolates, this meant weight changes could take minutes to propagate, not seconds

The `cache_hit: true` / `kvRead: false` in the `[route]` log refers to the ROUTE_TABLE Workers Cache (alias → canonical_slug). This is a separate cache and is NOT the cause of the issue — it does not affect variant weight selection. The actual problem is the in-memory AB config cache in `loadABConfig`.

## File changed

`functions/_shared/ab-router.js` — `loadABConfig` only. One logical change.

## Before vs After

**Before:**
```
loadABConfig(alias):
  if cached → return cached   ← valid config served from 60s in-memory cache
  read KV → validate → cacheSet(raw, 60s) → return raw
```

**After:**
```
loadABConfig(alias):
  if cached._no_ab_config → return null   ← sentinel: alias has no experiment
  read KV → validate → return raw         ← always fresh; no caching of valid config
```

## What changed

- Removed `cacheSet(cacheKey, raw, AB_CACHE_TTL_MS)` for valid configs
- Changed the early-return guard from `(cached && cached._no_ab_config) ? null : cached` to `if (cached._no_ab_config) return null` — valid cached data is no longer served; falls through to KV read
- `AB_NO_CONFIG` sentinel caching is unchanged — aliases with no experiment still avoid redundant KV reads

## What is unchanged

- Workers Cache (route resolution: alias → canonical_slug) — untouched
- Hub config cache (`loadHubConfig`) — untouched
- Global config cache (`loadGlobalConfig`) — untouched
- Bandit logic (`maybeRebalance`, `detectLeadingVariant`, weight computation) — untouched
- KV schema — untouched
- `cacheDelete(AB_CACHE_PREFIX + alias)` in `maybeRebalance` — still runs (now a no-op for valid configs, harmless)

## Confirmed behavior

- KV is always read for variant selection ✅
- Cache no longer affects experiment logic for RUNNING experiments ✅
- AB_NO_CONFIG sentinel still prevents redundant KV reads for aliases without experiments ✅
- weights change → traffic distribution changes immediately on next request ✅
