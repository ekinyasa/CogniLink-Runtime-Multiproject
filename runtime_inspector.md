# CogniLink Runtime Inspector

The Runtime Inspector is a secure, developer-only diagnostic tool that exposes the intermediate data structures generated by the **Shadow Mode** pipeline. It allows engineers to verify that the new `RuntimeContext` contract is being correctly constructed from legacy KV records without affecting production traffic.

## Nasıl Açılır? (How to Trigger)

Inspector, yalnızca yetkilendirilmiş admin isteklerinde devreye girer. Çalıştırmak için URL'e aşağıdaki iki query parametresi birlikte eklenmelidir:

1. `admin-verify=<ADMIN_TOKEN>` (Sistemdeki mevcut yetkilendirme anahtarı)
2. `runtime-debug=1` (Inspector tetikleyicisi)

Örnek Kullanım:
`https://cognilink.com/my-campaign?admin-verify=s3cr3t&runtime-debug=1`

Bu parametreler sağlandığında, sunucu normal HTML çıktısını veya redirect yanıtını **iptal eder** ve doğrudan JSON formatında `debugPayload` döner.

## Hangi Bilgiler Gösterilir?

Inspector, render edilen sayfanın arka planındaki veri hiyerarşisini tam olarak görmenizi sağlar:

- **`aliasResolution`**: İsteğin hangi alias üzerinden geldiği, cache durumu ve çözümlenmiş `canonicalSlug` değeri.
- **`repositoryResult`**: Adapter'a girmeden önceki ham KV verisi.
  - `rawLegacy`: SLUG_LINKS'ten gelen ham obje.
  - `rawV2`: Yeni APP_CONFIG'ten (Campaign + Page) gelen ayrık objeler.
- **`legacyObject`**: Orijinal `hubConfig` (veya `slugData`) objesi. Legacy pipeline'ın kullandığı asıl objedir.
- **`runtimeContext`**: Adapter tarafından üretilen, normalize edilmiş ve güvenli yeni sözleşme (`shadowData.context`).
- **`metadata`**: Render modları (`canonical` / `experiment`), kaynak şema (`legacy` / `v2`) ve runtime versiyonu.

## Güvenlik Modeli

- **Admin Only**: Inspector yalnızca `env.ADMIN_TOKEN` doğrulaması başarılı olursa çalışır. Normal ziyaretçiler veya token'ı bilmeyenler hiçbir şekilde bu JSON çıktısına erişemez.
- **Zero Impact**: URL'de parametreler yoksa veya token yanlışsa, istek %100 oranında mevcut production pipeline'ına düşer. Shadow pipeline hata verse dahi (exception swallow), kullanıcı normal sayfayı görmeye devam eder.
- **No Caching**: Inspector aktifken dönen yanıtlara anında `Cache-Control: no-store` başlığı eklenir. Böylece bu JSON çıktısı CDN veya Workers Cache tarafından saklanıp başkalarına gösterilmez.

## Production'da Neden Kapalıdır?

Inspector, doğrudan backend'in iç mekanizmasını (Ham KV kayıtları, internal ID'ler, component hiyerarşisi) açığa çıkarır. Bu veriler hem güvenlik hem de boyut açısından son kullanıcıya gönderilmemelidir. Amaç yalnızca cutover (geçiş) dönemi boyunca geliştiricilerin Adapter'ın davranışını canlı verilerle doğrulamasını sağlamaktır.

## Gelecekte Diff Engine Bu Inspector'u Nasıl Kullanacaktır?

Geliştirilecek olan **Diff Engine**, `legacyObject` ile `runtimeContext` verisini bellekte eşzamanlı olarak karşılaştıracaktır.

Diff Engine, uyuşmazlık (mismatch) tespit ettiğinde, tüm Inspector JSON paketini alıp **Analytics Engine (AE)** içine `AE_SHADOW_LOGS` olarak yazacaktır. Geliştiriciler bu logları inceleyip, Adapter'da hangi spesifik edge-case'in (örneğin bozuk bir component layout'u) atlandığını doğrudan Inspector'un sağladığı `repositoryResult` kısmına bakarak teşhis edebileceklerdir. Yani Inspector, sadece ekranda JSON göstermekten çıkıp, Diff Engine'in doğrudan hata ayıklama (diagnostic) formatı haline gelecektir.
